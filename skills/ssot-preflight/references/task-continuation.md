# Task continuation

## Existing task and evidence owners

Task and host workflows own execution. Route to existing progress, evidence, originals and live state.

**Pause or handoff.** When requested or required by the task workflow, update and reopen the authorized task record. Keep task identity, goal, success conditions, method, completed work and evidence, uncertain effects, blockers and next safe action. Link the governing goal, method or permission. Explain a failed attempt if a successor might repeat it. Use an existing task owner first. Create a task note only with authority to leave one; otherwise tell the user what could not be saved. Never keep a completed-task log in the entry README.

**Resume.** Match the exact task and record. Verify the saved method and next step against the current goal, scope, authority and completion evidence. If a premise changed, revisit the completed steps whose conclusions depended on it. Keep the observations and the work still supported. Apply an agreed stop or release condition only if its evidence and scope still match. Leave required human judgment pending. Exhausting a trial ends that trial; assess the goal separately. Record closure in the task owner, then remove any active task or handoff pointer from the entry README and active working lists. Writing a notice into a cancelled deliverable needs its own authority.

After a timeout or missing receipt, check the original operation's identity or authoritative outcome. Missing evidence leaves the outcome unknown. Retry within authorization only when evidence shows no effect or the same operation is effectively deduplicated. Pause the uncertain action and continue independent work.
