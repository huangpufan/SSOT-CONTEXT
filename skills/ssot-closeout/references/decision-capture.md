# Immediate decision capture

Use this route when visible user input settles a durable choice: confirmation, correction, rejection, or a limit on scope. Discussion-only work can settle a decision; a code diff is not required. An idea still under discussion remains a proposal. Apply closeout's write gates and memory-model ownership rules first; this route grants no authority to migrate an older SSOT, edit another repository, or change protected rules.

1. Read the relevant owner’s own writing, merge, source, index and validation rules first, then its source context. Establish acceptance and provenance using [human-decision evidence](../../ssot-preflight/references/memory-model.md#human-decision-evidence); this route does not override the project’s recording protocol. For a newly observed user exchange, preserve the user's words with the question or proposal they answer, the date, and who and what the decision governs (product runtime, repository working agent, or this task), with project and time scope. Product runtime authorization does not authorize a development agent’s external actions. Use a portable source link when appropriate; when a local source link cannot travel, retain the necessary quote and source ID instead. Keep only necessary source context, redact irrelevant private details, and retain project scope. If the reason was not given, say unknown rather than inventing one.
2. Update that owner now with the smallest sufficient record. Distinguish accepted choice from agent proposal, decision from implementation, and enduring rule from one-time task instruction. Route [goals and preferences](../../ssot-preflight/references/memory-model.md#goals-and-preferences) by scope and standing. An existing route to the owner suffices. Link an unreachable new owner if authorised, otherwise report the gap. Register a choice only when its source establishes a lasting constraint under [memory-model §5](../../ssot-preflight/references/memory-model.md#5-invariants): keep rows concise, when touching an invariant row whose `Source` holds verbatim quotes or logs (`>500` chars) offload them to `Explained in` or cold history while keeping `ID`/`Kind`/`Rule`/`Status` exact, and move a newly retired row directly into an existing cold retired shard. Use a decision record only when its consequential-choice threshold applies. When updating a [cold index](../../ssot-preflight/references/memory-layout.md#decisions), keep rows to one-line locators and collapse summary replays in the touched index. Reuse existing decision history or a topic section rather than creating an ADR or log entry for every sentence. Brevity must preserve every distinct constraint, exception, rejection and stated reason.
3. For a conditional method or default, explain [when it governs](../../ssot-preflight/references/memory-model.md#3-current-planned-and-unknown) in that owner. Replace only what the new decision changes, keeping unaffected clauses and their status, linking a superseded decision to its successor, and retaining historical source context; a correction never silently revokes other parts of the earlier decision. Remove any resolved `Open question`, `Known gap`, or completed `- [x]` checklist items in the touched entry or owner instead of leaving checked boxes behind.

   When a decision supersedes earlier guidance or the touched warm doc carries prior revisions, chronological logs, single-task receipts, or rejected trials inline, consolidate it in place under [compaction boundaries](../../ssot-preflight/references/context-tiering.md#compaction-boundaries): state current governing behavior, active exceptions, and a one-line cold link; **delete single-task verification/test-run receipts** rather than archiving them; offload superseded wording, rejected trials, and lengthy quotes to a separate cold file (`decisions/` or `<topic>-history.md`) by default so routine reads shrink, reserving trailing `## History (cold)` / `## 历史记录（冷读）` strictly for fixed single-file layouts (adding a 1-line offer to split files if desired). Never demote an active older rule by age; apply the [preservation check](../../ssot-preflight/references/memory-layout.md#preserving-content-when-reorganizing). Reconcile a known task’s now-misleading next step or entry route under [changed guidance](../../ssot-preflight/references/context-tiering.md#reconcile-changed-guidance), even if discussion ends here; batch closeout handles remaining uses.
4. Save, then reopen from disk before dependent work (you may run the post-write readback in the same tool step right after saving). Compare the saved question, verbatim user words when available, scope, status, reason and partial replacement with the source. For corrections, compare with the pre-edit owner's necessary source excerpts too; preserve their wording within current retention authority and mark the superseded scope. If capture changed the register, routes or other context structure, run `ssot-check.py` before ending this capture, including in a discussion-only turn ([selected checks](../../ssot-preflight/references/source-retention.md#selected-mechanical-checks) when restricted, otherwise `ssot-check.py SSOT --since HEAD` for format 4 or `ENTRY` for format 5). If `ssot-check.py` emits `compaction candidates`, apply safe in-place compaction on touched files (then re-readback and recheck); for untouched, external-owner, or layout-split candidates NEVER open untouched files, `memory-layout.md`, or `context-tiering.md`—relay the concrete target and action straight from the checker line (e.g., sharding `invariants/<topic>.md` + `invariants/retired.md`) in one crisp 1-line proposal and stop. Follow the settled decision in scope; new evidence or conflict can require another decision.

If writing is blocked, report the exact gap and keep the visible decision operative in this session; do not claim it is persisted. A persisted record proves capture, not that implementation exists or future agents will load it.
