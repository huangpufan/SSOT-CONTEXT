# Batch reconciliation

After the entrypoint's batch comparison, read [writing rules](../../ssot-preflight/references/writing-memory.md) before writing (reuse context). Read [layout](../../ssot-preflight/references/memory-layout.md) or [context tiers](../../ssot-preflight/references/context-tiering.md) only when you are actually creating/splitting files, writing a decision/research/workaround record, or actively reorganizing a touched file—never solely because `ssot-check.py` flagged untouched, external-owner, or layout-split `compaction candidates`.

2. **Protect people's rules, then write each change in its single owner.** Before altering a confirmed invariant, protected rule or accepted decision, verify an explicit human decision within the [decider's authority](../../ssot-preflight/references/memory-model.md#human-decision-evidence) meeting [memory-model §5](../../ssot-preflight/references/memory-model.md#5-invariants); without one, pause only the dependent work, report the conflict and ask instead of recording the new behavior as truth. Update in place using README routes and present tense, preserving accurate unaffected prose and describing an accepted exception within its scope while retaining the rest of the rule and its status. Record a lasting human-established rule or accepted departure as its own confirmed row with dated Source and scope; clauses of an earlier candidate row the user did not discuss stay candidate, and never move a confirmed clause to candidate.

   Follow [memory-model §5](../../ssot-preflight/references/memory-model.md#5-invariants) for concise register cells and topic shards: trim bloated `Source` cells (`>500` chars, keeping `ID`/`Kind`/`Rule`/`Status` exact on `confirmed` rows), and move newly retired rows into an existing cold retired shard. In touched files, delete verified resolved ephemera (resolved `Open questions` / `Known gaps`, completed `- [x]` entry checklist items, shipped `"Planned"` labels, fixed `gotchas.md` traps, met-condition workarounds, and closed Entry task links) and keep any touched [cold index](../../ssot-preflight/references/memory-layout.md#decisions) to one-line locators. Apply a one-task choice to the requested output, use a decision record only for consequential choices without an owner, and label decided-but-unbuilt behavior as planned. After saving, reopen each changed passage from disk (you may run that readback in the same tool step right after saving) and verify accuracy and cold-reader clarity.
3. **Reconcile and compact what changed.** Follow [changed guidance](../../ssot-preflight/references/context-tiering.md#reconcile-changed-guidance) on touched warm owners: consolidate superseded prose and chronological logs into current governing state, **delete single-task verification/test-run receipts** (commits/CI own them—do not archive them), offload superseded clauses, rejected trials, and lengthy quotes to a separate cold file (`decisions/` or `<topic>-history.md`) by default—reserving trailing `## History (cold)` strictly for fixed single-file layouts—and reconcile affected live uses and frozen dependencies.
4. **Check and act on compaction signals.** Check new or broader behavior claims, including final summaries, with [claim check](../../ssot-preflight/references/writing-memory.md#checking-behavior-claims), reusing step 2's disk readback when unchanged. Unless this batch stayed outside `SSOT/` and its routed documentation owners (no moved, renamed, or deleted files or linked headings), run `ssot-check.py` (reusing a check on the same unchanged result; [selected checks](../../ssot-preflight/references/source-retention.md#selected-mechanical-checks) when restricted, otherwise `ssot-check.py SSOT --since <commit>` from the batch's starting commit, using `HEAD` if uncommitted). Fix errors this batch introduced and those affecting what you wrote, and correct mentions of removed or moved files when they still describe current behavior.

   For `compaction candidates`: proactively compact touched SSOT-owned safe items now, reread edited passages from disk, and re-run `ssot-check.py`. For untouched pre-existing bloat, first-time layout splits, Format-5 multi-file splits, external canonical owners, or `confirmed`-rule rewording, NEVER hijack the PR diff and NEVER open untouched files, `memory-layout.md`, or `context-tiering.md`—relay the concrete target and action directly from the checker summary line into step 5's one-line proposal and stop. Report other out-of-scope errors and the scope checked.
5. **Report.** Carry the checked input conditions into the final response. Name the canonical documentation owners you changed and why; if you changed nothing, name the owners you compared and say why nothing in them became wrong or missing. When untouched or layout-gated `compaction candidates` remain, append one concise one-line proposal naming the concrete target(s) and action from the checker line and inviting a one-word "yes" or `$ssot-doctor`.

Put SSOT edits in the same commit as the change they describe, if the project's commit rules allow it. Committing and pushing follow the project's existing rules; this skill grants no extra authority.

You are done when every candidate is written to its owner or explicitly judged not durable, changed behavior claims agree with the evidence you checked, and, if step 4 ran the checker, it reports no errors in what this batch wrote, safe in-place compaction on touched files is verified, and any remaining untouched/layout-gated compaction candidates or out-of-scope errors are reported.
