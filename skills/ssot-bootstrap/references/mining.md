# Mining protected rules

During repository setup, reuse the source inventory and choose the review path below. Doctor area/history mining uses its declared scope and the [distributed area procedure](area-mining.md). For non-software evidence use the relevant canon, original material or accepted exchange.

## 1. Declare the scope before mining

**Setup dispatch gate.** Run `test -s SSOT/README.md` before starting miners, including on resume. If it fails, [save a trustworthy entry](bootstrap.md#2-write-the-readme-first), keep `BOOTSTRAP.md`, and rerun the check. A saved Next step cannot waive it.

Create `.ssot-work/.gitignore` containing `*` before saving scratch files there. List the main areas, source ranges and budget. Cover the whole small or medium repository; on large repositories identify remaining areas and history for Doctor. Give each area a first pass before repeating one.

Build one checklist from the actual sources: test files and names, fix/revert commits, changelog fixes, documented behaviors and option spellings, guards with a reason, and accepted or pending decisions. Account for each item with a proposal, an existing owner/row, an open question or a reason it supports no protection. Preserve decision standing. Give helpers scope and file/section links to the [evidence](../../ssot-preflight/references/memory-model.md#3-current-planned-and-unknown) and [admission rules](../../ssot-preflight/references/memory-model.md#5-invariants). Keep transcripts out of scratch briefs.

## Choose the review path

Use the compact path for setup when a writer and an independent reviewer can each check the whole unit, including dependencies and exclusions, against its inventoried sources. The existing owner must already let a newcomer carry out the main task. If operating guidance must be reconstructed across a public interface, implementation and tests, use [distributed area mining](area-mining.md) for that unit. One unit can span related areas. Split along actual owner boundaries or use [distributed area mining](area-mining.md) when the inventory exceeds that scope, a reviewer cannot account for an item, sources disagree about authority, or a lifecycle crosses an unexamined boundary. Trace callers and shared owners to determine which units that boundary affects. Escalate only affected units. Without independent review, leave progress and continue other authorized work.

1. The setup agent can write a compact unit using its first reads. Draft exact rows in scratch with their intended owner passages or links to existing text. Follow [memory-model §5](../../ssot-preflight/references/memory-model.md#5-invariants) for concise register cells (`Rule` = one governing constraint + primary scope; `Explained in` = one canonical owner section link; `Source` = compact attribution + date) and put aliases, flag matrices, rollout history, and detailed rationale in `Explained in`. Include conditions, aliases, precedence, exceptions, authority and implementation gaps in the explanation. Keep a decision with its governing conditions and exceptions, even across sentences. If attribution is genuinely ambiguous, name that uncertainty without changing what the authoritative owner requires. Keep inferred rows out of the register until checked.
2. Give one fresh reviewer the source locations. Start without inherited discussion, proposed wording or verdicts. Have it save independently derived outcomes from the underlying sources, starting with a different source type where available. Only then open the draft to challenge and check **every** proposed row and owner passage against the sources, including negative checklist items and possible crossings. For each clause check admission, exact wording and contrary cases. Preserve human decisions when implementation falls short. Check what discarded items promise as well. For a public CLI, read the help or help declarations: match each promised behavior, default, alias and prerequisite to the implementation. A documented promise verified there can support a candidate even without a test. When a public entry validates a request before a lower layer can skip work, trace a boundary input through both layers. Put the order and its user-visible consequence together in the owner, then test that distinction in the cold handoff. A list of flag names cannot account for those outcomes. Record omissions and the evidence for each verdict.
3. Publish checked wording to its authorized owner and register, then compare the saved passages with the reviewed versions. For missed or changed clauses, the author fixes the draft against the evidence. Return affected rows, explanations and dependencies for one recheck by a reviewer who authored neither the original nor the repair. Publish only checked text. Report still-disputed inferences as gaps. On resume, reuse a verdict only if its sources, owner and exact text still match; recheck changed units. Follow [setup progress](bootstrap.md#5-work-across-sessions) for interrupted work.

## Check the result with a fresh reader

Prepare ordinary work, failure/recovery and boundary requests. Include unaccepted crossings and nearby permitted changes. Test accepted departures where the actual acceptance and scope are available; otherwise report that case as untested. Give a fresh reader requests alone, with any original acceptance words needed to act. It starts at the README, follows owners and saves answers, sources and reading record. Score against held evidence: protect or ask on a crossing, proceed on a permitted change or an already accepted departure. Repair failures. This also covers the setup newcomer check.

After sealing those answers, sample checklist items randomly from every area, including items marked as supporting no outcome where present. Setup may reuse the reader; Doctor area/history mining uses a separate fresh helper. Supply that sample only now. Check reachability through the saved routes. Re-mine any missed part once, through the same challenge and check, and report the result.

## Report

For each area give sources read, proposals and their disposition (admitted, narrowed, rejected, deferred), admitted kinds, omissions the reviewer found and remaining Doctor scope. Keep `.ssot-work/` only while setup or a Doctor area-mining run is unfinished; once `BOOTSTRAP.md` finishes and is removed—or once Doctor area mining finishes and its saved outputs are read back—delete `.ssot-work/` (especially `convs/` transcripts) rather than leaving stale scratch on disk, and rebuild missing evidence before relying on it. Checker success alone establishes neither coverage nor truth.
