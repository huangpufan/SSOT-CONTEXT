# 4.0 project-memory behavior trials

The trials show bounded conformance on documentary tasks drawn from two real projects, a useful early-save ordering difference, and correct conservative handling of uncertain conversation provenance. They do not establish universal reliability or a clean pass of every original acceptance line. The original synthetic chat did not establish a new human decision; a separately authorized positive-origin simulation supplies that missing evidence without reclassifying the original case.

## Method and sources

Baseline is `88847dd`. All observed subjects use `gpt-6.1-sol`, high reasoning, through native Codex sessions, with a 240-second cap per turn and at most two subjects running together. There is no model judge or automatic protocol retry. Readback, native receipts and filesystem snapshots were reviewed separately from the subjects' completion messages.

Source excerpts come from Calliope's current project-control documents and 2026-11-05 asset-reorganization history, and dsh-personal-agent's LOOP decision owner, 2026-11-06 verification record and collection followups guide. Exact original paths, excerpt lines and file hashes live in the local manifest. These tasks maintain documentary excerpts; they do not execute the full projects or prove product runtime behavior. Conversation cases are explicit, deidentified simulations, not inspections of actual private history.

Within each pair the source and prompt match. The initial SSOT format marker is native to its arm (3 for baseline, 4 for candidate); each arm receives its frozen release adapter and ordinary skill paths. These are declared treatment differences, not instructions to force-read a particular new reference. Existing domain owners are routed from SSOT rather than copied into the fixture's initial memory. The runner masks host global instructions, skill discovery and plugins inside bubblewrap without modifying host files or repurposing CODEX_HOME. Saved `codex debug prompt-input` readback shows the host discipline and skill catalog absent. A no-model child process actually read, wrote, read back and removed its owned smoke file. Subjects have no remote and are instructed not to use network tools, other models, commits, pushes or external actions.

The owner, decision, merge and DSH generation runs use the earlier candidate snapshot. Chat, positive-origin chat and the fresh reader use a separately frozen final snapshot after review added origin/scope/owner and rescan clarifications. Both snapshots and intermediate hashes remain. The results must not be presented as one exact-body trial of the final bundle.

## Acceptance and observation

Before each run, the frozen plan requires existing owners to remain authoritative; decisions and real reasons to survive before unrelated work; native corrections to preserve history and limit scope; asset consolidation to lose no supplied item, status, quantity, name or provenance; DSH authorization and test claims to retain their actual scope; unrelated command and read-only tasks to make no memory writes; and short conversation answers to be interpreted with their questions and later corrections, excluding unsupported assistant and false-origin messages. Planned design must stay distinct from story progress or implemented product behavior. Missing sources must not become a claim of whole-project or whole-conversation coverage.

The initial chat deliberately contains a user-label selection, a later correction, assistant overgeneralizations, and explicit worker/compaction user-role messages marked nonhuman. Its title says it is synthetic and not an original conversation. The candidate therefore correctly treats the apparent selection as an unverified lead; this does not satisfy the original positive-capture line. The baseline still replaces the existing U13 using that unverified user-label content. The original prompt, outputs and unmet line remain unchanged.

A separately authorized `chat-origin-positive` pair fixes the input evidence, not the original verdict. Its generator supplies stable message IDs, explicit simulated human-origin verification and false-origin counterexamples. A full question states the older broad internal-delegation protection and the loss caused by narrowing it; the simulated human explicitly accepts that exact loss and supplies a reason. Later messages correct the numeric and external-action overgeneralizations. Identity authority exists only inside this simulated repository; it is not real platform authentication. Both arms receive the same independently frozen source and prompt.

Saved output is read back from the actual owner. Event checkpoints observe JSON event boundaries, not every possible intermediate write; native dispatch/completion receipts and shell mutations are reviewed separately. A final correct document cannot establish a safe earlier interruption boundary, and a completed CLI turn with blocked tools is not success.

## Preparation defects and retained failures

The initial excerpt producer supplied invalid optional `reviewed_through: fixture`, hyperlinks to omitted targets, and an already-corrected whitespace example. Its owner pair and one initial baseline decision remain exploratory. Owner routing and unchanged docs can be observed, but these runs cannot count as a clean structural gate or prove early-before-unrelated-write ordering. The producer was corrected for both arms: omit the optional invalid field, render omitted-target links as unchanged readable labels with original coordinates retained in the manifest, and generate exactly one editable whitespace occurrence with an assertion. `fixture-revision-2.json` freezes the revised material; historical input and outputs are not patched.

The runner also had reproducible infrastructure defects: a read-only device binding blocked the proxy wrapper before any model event; nested sandboxing needed writable temporary metadata and user-namespace mappings; and native resume did not inherit the first turn's sandbox selection. The runner now uses an ordinary empty instruction file, a device filesystem and writable temporary mount, and explicit sandbox mode on every turn under the outer bubblewrap boundary. Six model-blocked turns and two pre-model starts remain recorded. The blocked native correction second turns stay beside the successful unchanged-prompt third turns, rather than being overwritten or credited as successful protocol execution.

## Separate migration and local verification

A separate fresh `gpt-6.1-sol` agent migrated a synthetic v3 consumer under its own frozen snapshot. Independent readback records 11 passing assertions: only README and adapter changed, no existing file deleted, prior README content retained apart from the format marker, original confirmed/candidate rows unchanged, review watermark unchanged, unmanaged instruction text unchanged, owner/decision bytes unchanged, format 4 set, no surviving bootstrap marker, external owner routed, and checker zero errors/warnings. The subject reports creating then removing a bootstrap marker; the independent observer directly confirms only its final absence. This is a synthetic migration, not a real consumer migration or interruption test. Evidence is `/var/tmp/ssot-v4-migration-icf4h4u0/evidence/verification.json` and neighboring before/after hashes, diff, protocol manifest and checker readback.

The trial recorder passes `python3 -m py_compile tests/run-memory-trials.py` and `bash tests/test-bundle-shape.sh` (48 passed, zero failed). These validate the runner syntax and bundle structure, not model semantics. Broader release checks are recorded by the maintainer separately.

## Evidence and limits

Raw local evidence is `/var/tmp/ssot-v4-trials-tvzkj0ul/`: source/fixture manifests, frozen adapters and bundles, prompts, isolation/smoke readback, native JSONL, successful-write checkpoints, final messages, independent merge and decision readback, and `all-attempt-metrics.json`. It is local evidence, not a portable public dataset. No separate model-grading campaign ran.

The original unverified chat remains unresolved as positive capture, earlier-candidate generation is not relabeled final-body validation, and this sample does not test a connected-conversation integration, complete private-history mining, real platform identity authentication, actual interruption recovery or full consumer-project execution. It establishes the reported cases and boundaries, not universal reliability or lower whole-task cost.
