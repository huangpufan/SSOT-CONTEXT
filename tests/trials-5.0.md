# General context: implementation and mechanical evidence

Bundle 5.0 adds explicitly maintained general context spaces while preserving development consumer format 4. New general spaces use format 5 because their authorized-record admission and cross-space owners must not be silently interpreted by an old development writer. The [accepted direction and compatibility matrix](../docs/context-generalization-2026-11-10.md) distinguish this implementation from its release gates. The unchanged baseline is bundle 4.5 at `7c15dd8`.

This file owns the implementation/mechanical evidence summary. The [native report](context/trials-5.0.md) and [native result account](context/results/context-evolution-5.0-2026-11-10.json) own actual model attempts, original/repaired oracle judgments, manifests, receipts and whole-task costs. Native trials are separate evidence; successful CLI or checker tests do not establish agent discovery, semantic acceptance, useful writing or general cost improvement.

## Implemented boundaries

The four primary skills retain their names and add an explicit format-5 route. Development format 4 continues normal authorized upkeep; known v2/v3 remains read-only pending agreed preservation-aware migration, and unknown/future formats receive no downgrade offer. General setup uses its own continuation/completion conditions, without requiring Git or applying software-only mining to a life/research space. Its two-field entry marker and prose routes retain existing owners rather than imposing a universal item schema.

The conditional [space model](../skills/ssot-preflight/references/context-spaces.md) distinguishes evidence, acceptance and scope; authorized records can be retained without a knowledge-extraction usefulness test. Protective candidate rules retain their existing meaning. Facts, hypotheses, personal testimony, accepted choices, preferences, experiences and changing state follow their respective evidence and ownership boundaries. Top-level spaces can own relationships and tradeoffs; a route does not grant access or waive a child protection. Direct-child discovery gaps remain explicit.

The optional POSIX [source CLI](../skills/ssot-doctor/references/source-integration.md) supplies a connector-task boundary, not a provider collector, scheduler, second document archive or permissions service. Trusted invocation supplies allowed source/scope and owner bindings. State stores source metadata/digests/locators and registered effects rather than source prose. The agent still interprets source material and writes authorized owners. Actual updates require each declared/affected owner's saved readback; a considered no-update outcome requires a reason and cannot bypass in-flight output. Artifact pointers verify exported locator identity, not the referenced bytes.

## Continuous paths and counterexamples

[Source contract tests](test-context-source.py) execute the real CLI in isolated temporary directories. The separately authored [source checks](context/test_source_contract.py) exercise the same public boundary; neither runs a model. Their observations are limited to the synthetic files and declared owner set.

| Boundary | Observed counterexample and repair |
| --- | --- |
| Readback → no-update | An owner marker/readback before completion could be discarded through no-update. Actual current/historical captures, receipts and references now block that shortcut. |
| In-flight owner → route move | Binding an empty new owner could hide a capture written before readback. Rebinding now requires known real markers and receipts to survive the authorized move. |
| Targets A/B → targets B | A reasoned target change could omit A's actual unfinished output. Completion now includes current-record effects too. A real reversal restoring A's original bytes can finish B without inventing an owner diary. |
| Source withdrawal → recovery | Withdrawal originally listed only completed references, omitting in-flight writes; subsequent status also lacked them. Targets, receipts, references and located captures remain inspectable without reopening source prose. Withdrawal now gates import before any export read. |
| Revision replacement → replay | A completed successor originally left an older pending revision processable; a later upsert could bypass the replacement relation. Known successors now block ordinary old-version processing; explicit history is read-only. Unknown/ambiguous targets conflict. |
| Sibling revisions → current owner | Competing children of one parent could both complete and overwrite by execution order. A justified resolve-fork now locks the observed sibling set and choice; later siblings invalidate that choice, while a selected linear continuation works. Other conflicts and withdrawal remain protected. |
| Readback → intervening edit | Changing an owner after readback invalidates its whole-file receipt. The caller rereads actual content before progress; no block parser or cross-owner transaction is claimed. |

Real CLI reproductions were retained before each mechanism repair. The source regressions cover the fixed paths and nearby controls, including correction before predecessor completion and actual reversal. They inspect saved owner bytes and processing state rather than trusting the tool's final success wording. The tool still cannot certify semantic correctness, human acceptance, all downstream copies, power-loss durability or malicious-writer containment. Source-looking marker syntax in imported prose is evidence to interpret, not an actual tool receipt.

## Checker, installation and local checks

Format-5 checks cover the selected entry and directly linked local owners. Named external filesystem routes receive target metadata existence checks without crawling their text; missing targets fail and inaccessible metadata remains incomplete. Absolute-path portability warnings remain, but no longer skip format-5 existence/local-owner checks; format 4 retains its old behavior. Remote URLs remain outside the check. A native-produced `保护规则` heading exposed a register-recognition gap: adding that single alias enables actual row/status/history checks, rather than hiding the warning or rewriting the native artifact. Final read-only checking of the same C07 tree reports no errors/warnings with unchanged bytes. Named entries retain the confirmed-rule history guard when Git is available. No-Git limits are disclosed. The old 4.5 checker rejects format 5 without changes; agent compliance/discovery is separate evidence.

Installer e2e exposed an actual release-generation defect: its upgrade warning matched only a new 4.x, so 2/3 → 5 omitted old-memory read-only guidance. The version boundary now recognizes the current major and uses accurate format-4 continuity wording. A separate development-format-4 → current control observes no migration requirement. Existing installer rollback/recovery behavior remains intact.

Local checks on Linux with Python 3.12.3 include source CLI regressions, independent source contracts, checker history/route regressions, benchmark and migration self-tests, installer e2e and recovery, bundle/size checks, ShellCheck, compilation and changed-document links. Commands and exact observations belong to the [mechanical result account](source-results-5.0.json). Linux/macOS CI runs the new offline suites and compiles the new scripts; a configured CI job is not evidence that the pushed candidate has passed it. The optional CLI uses POSIX `fcntl`; Windows is not established by these tests.

The final source's operation metadata and marker/history clarifications are a documented small delta after the frozen v4 native source. Its targeted CLI status/latest-withdrawal/history check and both source suites ran against the final bytes. The native result account retains v4's own source identity; it must not be relabelled as a complete native run of the later hash.

## Independent review and unavailable reviewers

Opus 5.5 and Fable 5.1 returned architecture reviews; Sonnet 5.5 returned code reviews of frozen v1 and v3. Findings were checked against the contracts and actual CLI behavior before changes, including the target-shrink counterexample. Review output is evidence that review happened, not proof that the implementation works. Source revisions after those snapshots retain their own test/delta identity.

This round's Kimi and Flash implementation-review attempts did not return usable answers: first attempts reported transport failures, subsequent v3 calls reached their 600-second budgets, and a smaller Flash source-only v4 attempt reached 180 seconds. These are unavailable implementation reviews, not successful checks. Earlier design-discussion responses are separate evidence. Endpoint reachability alone does not identify a failure's cause; no cause or review pass is inferred. The mechanical result account preserves these reported scopes and artifact references without counting them as native behavior trials.
