# Context 5.0: native evidence and limits

This report records the independent context-evolution validation on 2026-11-10. The task required generic maintained spaces without losing development protections, authorization, decision continuity or selective reading. The coordinator directly reread the principal saved owners and responses; the independent validator checked native receipts, executable outcomes and ordering. Overall release acceptance and final Git/CI checks remain the coordinator's responsibility.

The [versioned machine inventory](results/context-evolution-5.0-2026-11-10.json) is the quantitative owner: frozen bundle/harness manifests, every attempted turn's actual model, input/output usage, elapsed duration, receipt hashes, original/repaired verdicts and representative recovery states. Raw prompts, streams and before/after files remain in the inventory's local `evidence_root`; large transcripts are not copied into this repository.

Warm total tokens increase by 4.8%, 10.3% and 12.5%. No unrelated generic/source reference is loaded. The same common preflight/closeout/model files add 1,153 fixed bytes per full first read, but that does not explain the whole token change. First-turn decision-capture reading occurs in one baseline and all three candidates; protocol-entry rereading occurs in two baseline second turns and one candidate. Across warm tasks, runtime source bytes commanded/tool items are respectively 34,456/14 versus 25,231/10; 34,016/11 versus 39,507/13; and 25,220/12 versus 29,391/13. Relevant project-owner reads remain equal at 6,089 bytes per task. These byte counts are distinct from returned tool bytes and native tokens.

The first pair consumes more candidate tokens despite fewer reads/tools. Branch selection, batching/repeated model context and provider variability are not causally isolated; the long warm-2 candidate also exhibits connection/provider delays. There is no latency-improvement or general cost-improvement claim. The coordinator accepted this bounded implementation tradeoff for the added responsibilities without compressing protection/recovery rules. That is the coordinator's judgment in this task, not a claim that the user had explicitly accepted a particular token increase.

## Failures and evidence repairs retained

- Four unexpected incomplete native turns remain: general C02 baseline, general C03 candidate correction, general v3 read-only baseline, and serial C03 baseline. Explicit reconnect errors establish a transport boundary in several streams; a timeout without that evidence is not automatically classified as infrastructure. Completed writes and all observed usage remain. C02/v3-read-only later complete under a newly frozen 420-second serial experiment; the second C03 baseline timeout is retained without repeatedly rerunning for green.
- A C05 oracle wrongly required the default entry path despite a valid personal owner entry. A D06 oracle treated `rg --files` with an exclusion glob as reading SSOT content. C03 source-name/date co-occurrence was insufficient to establish correction handling. Frozen revised graders, positive/negative checks and separate repaired verdicts re-evaluate the same saved artifacts; original verdicts remain. No model rerun sought a better output.
- Pre-model installation first inherited read-only snapshot modes into installer staging; the owned copy generator now restores normal owner-write modes while proving identical source bytes. Another zero-model probe used a debug-unsupported flag. Both failures remain; a new actual installation/discovery probe succeeds. These are not native skill-quality failures.
- Source V1/V2/V3 composition defects were caught before source native calls: inflight no-update/withdrawal/payload opening, inflight owner rebinding, and same-revision target shrinking. Independent real-CLI regressions fail the earlier snapshots and pass all 12 checks on the frozen V4 helper. Broader fork/relationship regressions remain in the implementation's separate mechanical evidence; they are not relabelled native scenarios.

## Final deltas and remaining limits

Paid source/installed behavior uses helper `ee86a3f13a0b`. The final working helper `42037ea5a61a` adds operation metadata and source-purpose/history prose after the freeze, without changing the accepted execution guards. Its targeted CLI checks are separate evidence. The native C07 candidate honestly reports one Chinese protection-heading warning. The final checker adds the missing alias and absolute-owner mechanical checks; a later read-only run against the unchanged C07 tree reports zero errors/warnings. Original native output remains unchanged. Neither mechanical update is claimed as a new final-hash native run or validation of the entire owner graph.

These small synthetic local tasks establish the named paths, not universal reliability, automatic background ingestion, all-provider connectivity, unseen conversation recovery, old-writer discovery of arbitrary unlinked entries, cross-machine recovery, external-owner ACID transactions, power-loss/mid-write recovery or erasure of every copy/cache. Raw originals remain with their owners; summaries/receipts are not replacements for source evidence. Creative quality and broader product preference remain human judgments.
