## 接下来怎样决定

优先处理真实生产中高频重复出现的瓶颈，而非继续在合成小文档上微调 1–3 KB 文本拆分。现已落地 `install.sh --check-block` / `--sync-block` 与事务卸载、`dsh` 注册、`5.17` 主题分片、`5.18` 收尾检查减噪与默认 4 核心技能瘦身安装、`5.19` 即时决策采集内联结构检查、`5.20` 批量收尾快速结束/条件 `memory-layout.md`/同步骤落盘回读（采纳 5.20 的 P3）、`5.21` 只读预检直出（E2）与跨格式 `task-continuation.md` 抽离/保护前置/热路径去重（E3）、检查器多 worktree 与分片可达性加固、以及零 token 的可选 Git `pre-commit` 守卫（`tools/ssot-precommit.sh`）与 worktree 安全软链（`tools/link-local.py --absolute`）。同时已用冻结配对实测明确排除六类无效或反效果方向：子 Agent 适配器跳过条款（P1）、`SKILL.md` 局部快路径分片提示（F3）、父级委托简报约定（5.20 的 P4）、写前乐观三方比对（5.20 的 P5）、格式 5 收尾短路由（5.21 的 E1）以及条件加载 `memory-model.md`（5.21 的 E4）。下一阶段优先在重型消费空间落盘 `5.17+` 分片、最新指令块与 worktree 安全安装并持续多周复测真实会话分布，同时按需有界评估 [Stage 5 审计](2026-11-24-real-session-stage5-audit.md) 留存的可选单宿主只读 Hook 原型（原记作 Stage 5 优先级 3，区别于 5.20 已采纳的批量收尾候选 P3）。试点前一周的 48 条用户消息里，6 条明确问进度、取舍或原因；下一位问进度的人，仍应能直接从本页得到简短答复。已明确负责人和范围的公开文档，可由当前维护者就地处理；需要受限原件时，仍由负责人提供授权材料。
