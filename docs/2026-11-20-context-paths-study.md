# 一次交接究竟需要读多少协议

一个维护者要回答“现行做法是什么”，另一个要改变它。两人可能从同一份文档出发，只有后者需要辨认谁有权改、哪个旧条款被替代、哪些地方需要写回。反过来，一次看似简单的只读交接也可能马上导致印刷或重放请求，必须先查权限和回执。我们从这几种行动的后果审查 5.13。发布判断同时看现行交付、下一个人能找回什么、为了做到这些要读写多少。

**本轮保留 5.13。** 第四个候选在实际交错的编辑中保住了两人的可执行决定，但超时后下一个人仍无法找回被替换偏好的唯一理由。按用户确认的边界，只交付可复跑的候选、实测与门禁修复。详见[整组结果](#发行裁决与整组实测)及[逐阶段回执](../tests/benchmark/results/context-paths-study.json)。

## 实际入口与既有能力

起点是 5.13 的 7665792。只读抽查三个不同形态的本地入口。桌面软件的 16,733 字节入口把任务连到运行时职责、产品边界和平台验收。研究空间有独立的方法说明和交接说明，共 12,346 字节，方法的局限、证据等级和当前能继续做的工作各有位置。长篇创作的 17,697 字节具名入口有作品边界、材料地位、任务路由、约束和待决事项。研究空间已有自己的文档结构，观察它并不授权建库。观察限于入口和方法结构，没有从私人原始资料抽样，也没有测得它们自然发生的遗漏率。讨论用匿名概述，试验用可公开复跑的材料。

盲审后又只读核对一个个人空间入口。该入口已有格式和语言标记，12,305 字节、8 个标题、31 个本地 Markdown 链接。只检查入口结构，没有打开下游个人材料。这个样本补充多主题路由的安装观察，无法说明其所有者如何在预算不足时作出取舍；个人组合决策在本轮仍是审计反例。

[5.10](2026-11-20-context-lifecycle-v5.10.md) 已经区分任务进展、长期方向及断点。[5.11](2026-11-20-goal-changes-v5.11.md) 处理改目标后的旧下一步和在途动作。[5.12](2026-11-20-conditional-context-v5.12.md) 处理条件生效、撤回和局部替换。[5.13](2026-11-20-context-stewardship-v5.13.md) 已试过授权交接、来源独立性和唯一历史理由。上次七班的发布版比纯文档多消耗约 95% 的输入，最后一问找回了作者和理由。一次展馆案例无法回答跨领域的成本问题。5.13 的运行时文本只剩 96 个词余量，整个技能目录只剩 166 字节。决定先看能取消哪些人人都付的成本。

主观喜好在作者或决策人接受之后才获得相应地位。重复行为可以提供进一步询问的线索，无法自行升级为长期偏好。纯讨论中确实确立了长期做法，仍应在下一步依赖之前按既有权限捕获。当前试验没有观察不可见会话的漏捕率，也没有把宿主未加载的技能算成已执行。

## 同一任务怎样付费、如何判错

主工作量在看到第一份原生回答前固定为每组 22 个阶段。运输报价两次各执行 144 个边界输入，第二次 HEAD 相同，维护者已经改了脏文件并新增规则。研究报告使用真实发表的 14 份阶段回执和 26 个历史版本去追问一项因果判断。创作包含两次换班和第三位编辑的实际提案，要读正文评估人物目标、师傅争执、未采用的茶摊、两个可行方向及取舍。编辑合入包含同祖先的两种并发改写，各有下一位印刷人员只读接班。另测两种格式的只读查询、受保护行为的偏离请求、两种格式的纯错字。最后用同一展馆在七个独立会话里逐步改变任命、证据与标题，实际产出内外两版简报，并追问已退役偏好的作者与原由。

普通文档组得到完全相同的项目入口、资料、任务和写权限。安装组另外得到所比较版本的六个技能和正式安装器给出的接线段。每阶段都重新开宿主会话，只把项目里的文件交给下一班；各组磁盘和会话隔离。行为裁决观察修改后的文件、实际调用和冷接手者能否正确行动。受保护偏离的正确结果是保留源码并具体请示。实现用户未委托的其他积压工作也构成越界。错字必须只改指定文件，另计多余的技能读取。工具级观察不能证明未被记录的读取。压缩回归同时看既能制作现行简报又能查回唯一历史理由。

Terra 的输入、缓存输入和输出取自原生 turn 回执。Flash 使用 DSH 原生 headless，逐条核对 agent-plan 的响应身份。其输入按每步 `totalTokens - outputTokens` 汇总，已包含缓存；另列 `cacheReadTokens`。两种宿主的原始数字分别比较。Flash 另会为新会话生成标题，原生记录给出请求和所用模型，没有逐标题 token 账单。表内因此是有回执的任务用量，不能据此结算金额。Tool 输出量取已记录的返回正文。Terra 的读取数是包含常用文件读取命令的 shell 调用数，写入数是采样观察到的树变化次数；Flash 分别计读工具或带读取命令的 shell、以及明确写工具。shell 也可写文件，以实际变动路径复核。缓存的计费取决于服务，各阶段失败、未开始和未返回用量分开列出。

附加回归用真实检查器在选定的两个文件间制造并修正坏锚点，再跑同一命令。另用编辑者确实读到旧正文的工具回执触发同事写入，分别合入互补修改或把重叠范围交给裁决者。两类测试与主分母分开。用于调度的临时 Python 文件曾与标准库重名，机械门禁首次启动时意外触发了一次 Terra 编辑试验。已隔离门禁工作目录并更名。该调用保留在补充账中，不给候选加分。

三类真实空间仅用于确定需要验证的问题。代码和受限检查器实际执行，研究数据来自历史发行与公开试验，创作和展馆按真实工作流程构造但人物是试验设定。本次没有在真实消费者中编辑、部署或追踪数月，也未请真实作者评价主观喜好。每组每种任务一次，无法估计总体命中率。维护者编排并读产物裁决，外部设计讨论和行为试验分别使用各自获准的模型。

## 候选的边界与淘汰过程

1. **这项责任为什么共用。** 在软件、研究和创作中，一次决策只应改动获授权的范围。源材料、验收方法、任务执行和取舍权继续由原项目拥有。比较同一段的旧版、当前版和拟写内容属于写入路径；有条件更新的事务性属于宿主。
2. **用它替换什么。** 首个候选把两个格式的日常读取、捕获和收尾合成共用路径，删除日常任务默认预读的模型章节，把各格式的初始化、来源与检查入口留在条件分支。第一次七班试验生成了正确的当前简报，却抹掉 Cora 为什么选择项目符号的唯一出处。该版本淘汰。下一版在真实限定文件试验中仅自行检查了两个文件，未运行安装的检查器。又一版恢复直接可到达的理由保护和正式结构检查，仍在 Flash 的受保护请求中实现了无人委托的功能。
3. **按哪个用户动作复验。** 第四个候选将“只保存已定选择或记录交接”直接交给 Closeout，其他实质工作从 Preflight 开始。写入前仍识别当前 owner、保护与原由；中止时仅继续另获委托的部分。相同库存条款从共同祖先被原样带入，不能算另一位编辑重新接受该条款。先重放出错请求，随后保持同一套 22 阶段分母，同时触发真实并发写入。基础、候选与纯文档的每个观察都保留。
4. **全任务净效应怎么裁决。** 入口字数、某个短问和一次正确请示都不足以发行。既要核对实际可运行代码、理由来源、下一位作者能否继续、普通任务是否被误触发及附带写入，又要与当版、纯文档分别比较全工作量的成本。格式 4/5 的数据与检查接口继续兼容，预算上限维持原值。

维护者同时发现包体门禁从仓库外运行时可以读错相对文件，显示 0 字节并通过。用独立副本插入 237,569 字节文件，旧门禁仍通过。修正后同一工况报告 469,827 字节并失败，移除该文件后在仓库内外均得到 232,258 字节并通过。Markdown 文件列表使用 NUL 分隔，读取失败会中止相应验证。这个缺陷会直接使“符合运行时预算”的证据失真。

repo=$(git rev-parse --show-toplevel)

## 安装与验收

只读盘点 88 个已知入口路径，62 个链接入口逐文件等于源码；两个独立副本也等于当前 5.13；24 个历史路径已经不存在。入口路径包含不同宿主的别名。三个真实消费者共有七个抽查入口。将消费者文件系统置为只读后，分别从三个工作目录启动新的 Codex 发现探针，三个均返回六项技能和已接线的项目指令。这个观察覆盖新的宿主发现过程；已有常驻会话可能仍用启动时的上下文。消费者项目没有修改或重装。

在候选与交付树分别运行了包形状和预算、机械检查器、benchmark 与 context 单元、迁移、来源、本地链接、安装端到端、安装恢复、ShellCheck、语法和 Mermaid 渲染。包括 138 个检查器测试、68 个 benchmark 单测、97 个 context 单测和 123 项安装端到端断言。格式、安装版入口、双语模板与候选实现的身份分别核对。公共主分支的 `VERSION` 和 `metadata.protocol_version` 均为 5.13。后续若要引入带历史保护的写入器，需要先明确原文可否留存、谁拥有修改权及宿主能否原子提交；这项新能力留待单独裁决。
