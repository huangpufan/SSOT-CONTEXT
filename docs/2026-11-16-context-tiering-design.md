# 让日常读取变轻，同时保留能追溯的理由

用户先指出 Calliope 的决策历史和控制页膨胀、旧内容没有随新决定完整更新，随后提出借鉴数据库的冷温热分层与压缩。2026-11-16，用户确认这个方向，授权与 agy 讨论、完善并实现 SSOT 设计、安装到 Calliope，并验证 agy 能实际发现和读取 skill。本次范围是共享协议及安装接入，不包括改写被冻结的小说正典或更改全局 agent 配置。

成功意味着：常规任务能从小入口到达足够的现行知识；需要理由或遇到歧义时能准确回查历史；部分更正保留其他约束，旧例子和摘要不继续冒充现行依据；冻结资产明确待同步。成本以完整任务的读取、检索、写入和错误衡量，不能仅以文件变短代替。

## 讨论及裁决

通过 Calliope 已有 `agy_bridge` 与 Antigravity 原生会话进行两轮只读讨论。请求型号为 `gemini-4-carbon-medium`，响应回执为 `gemini-4-carbon`；实际推理档位未独立回显。第一轮提供用户需求和原始文件，要求独立找反例；第二轮对设计取舍及第一轮意见作交叉质询。原生轨迹确认 agy 读取了技能和相关文件，完整原返保留在本机任务证据目录。

采纳的重点是：按任务必读性和漏读代价分层；温层持有整理后的现行理解；冷材料定向取回；冷热不决定规则是否有效；冻结边界不能被维护任务越过；避免全局访问计数、强制新目录和治理账本。

第二轮补充了即时决定捕获的入口一致性、冻结提示应具体到旧概念和当前章节，以及必要冷回溯的反例。它们进入共享协议。常规任务不通读历史，不等于禁止为判断边界读取一条历史。

以下意见经核对后收窄：原始历史不能被规定永久只增不删，仍受授权保留、撤回与删除约束；数据库增量合并的类比不成为第二套终态事实表；Antigravity 旧全局路径并非所有表面都不支持。官方文档区分 App、CLI 与独立 IDE，因此新增 App 的共享路径入口，保留旧 key 的作用与升级/卸载路径，不搬动本机全局安装。

## 协议归属与变化

`context-tiering.md` 是共享协议 owner。按需整理部分解释热入口/任务工作集、温层主题 owner、冷历史与来源，以及压缩后的保留和回查。变更对账部分接替原有 development batch-closeout 第 3 步，供 format 4 与 format 5 共用。即时捕获先刷新已失真的入口和待同步边界；批次结束覆盖剩余相关在用材料。

路径和普通阅读继续由已有入口持有。新知识和历史不迁入一套新存储；短摘要有 owner 指针，并随 owner 的相关变更对账。具体旧词检查留在消费者已有检查器中，共享协议同时要求核对语义，避免换名复活。

维护过程的关键转移是：相关主题进入本次工作集；已接受更正更新其知识 owner；受影响的在用材料同步，或明确成为待同步资产；获准解锁时重新以当前 owner 为准完成同步。历史被取回仅改变本次访问，不改变接受状态；压缩仅在保留检查完成后替换受影响表述。需要的来源不可访问时，保留具体缺口。

## 代价与验证

新分支不可能零成本。运行时协议总预算从 17,000 调到 18,000 词，其他预算不变；未删无关权限或恢复规则凑预算。分层整理按需加载，变更对账承担明确的读取成本。宿主控制已有会话内容的卸载，文件整理本身不能证明省 token。

试验使用允许的 `gpt-6.1-terra`，基线为 5.3，候选为 5.4。比较部分更正、入口整理后全新会话产出、必要的定向历史回查、development 部分更正回归及拼写负例。实际结果、失败和完整成本见 [5.4 试验报告](../tests/context/trials-5.4.md)。

## Calliope 安装后的实际读取

项目已安装 5.4，agy 与 Codex 的全新原生会话都发现六项技能，实际读取 preflight、doctor 和新的分层参考，并完成限定范围的只读审查。agy 在升级前也已读到 5.3，因此未复现“项目技能完全不可读”；本次证据不代表旧会话会自动刷新。保留共享物理目录与软链，新增明确的 App 安装入口和完整读取技能的接入说明，没有修改全局配置。

实际试读留下两项后续内容审查线索：agy 指出开工必读的锁区待同步表重复了大量替代细节，应该在获准整理时改为受影响主题、当前 owner 章节与解锁条件；Codex 指出 README 的相关引用阅读路径与控制页的锁区阅读限制存在表述张力。这些内容没有在本次安装中改写，冻结正典也保持原样。它们是下一轮从真实维护需求继续改进的输入，不能被安装成功或机械检查通过掩盖。
