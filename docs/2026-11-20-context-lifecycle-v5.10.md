# 5.10 面向接续的长期 context

长期工作的下一位执行者需要读懂当前目标、采用的方法和已经发生的事，才能判断下一步。5.10 从 `913eca9` 的 5.9 出发，针对两类实际可见的故障做了改动：Agent 将偏好当成受保护规则，以及开发仓库没有办法让检查器只读取获准的文档。相同的协议也把两个格式的暂停与恢复入口接了起来。

## 从下一步需要什么出发

| 下一位执行者需要知道 | 5.9 提供什么 | 5.10 怎样处理 |
| --- | --- | --- |
| 目标是什么，怎样算达成，何时停下 | 开发格式描述项目意图与承诺。通用格式区分已接受目标和建议。 | 两个格式共享目标语义。长期目标留在主题 owner，任务目标和验收条件留在任务记录。变更后核对依赖旧条款的待办及证据。 |
| 为什么采用这种方法，何时重看 | 研究、流程和决定文档可承载方法和理由。试行方法可能被写成永久选择。 | 方法说明适用条件、验证方式和重看的理由。已授权的试行保持原边界，备选方案按其实际接受状态记录。 |
| 哪些动作已完成，哪些效果仍未知 | 任务和证据已有各自的 owner。普通接续规则主要藏在写作布局参考里。 | 在暂停、交接和恢复时从两种入口进入同一条按需路径。新会话核对任务身份、现有证据及下一步。缺少回执时查询原操作或权威结果，保留未知，继续独立工作。 |
| 哪些习惯是默认，哪些规则必须守住 | 决定来源与硬规则有明确保护。5.9 的两个实际写入场景都把软偏好与登记不变量混淆。 | 保存偏好的持有人、范围、例外和出处。单次授权可以覆盖默认值。长期要求继续进入不变量登记，已登记的规则继续按原权限裁决。 |
| 为什么相信旧决定，哪些材料还能使用 | 两个格式检查决定来源。5.9 的受限 checker 只接通通用格式。 | 未验证的人类接受维持未决，候选规则仍需有独立保护证据。两个格式都能选择获准文件进行结构检查，并区分停止使用、撤回、替代和删除。 |
| 什么算维护完成 | 立即保存决定后回读，批次结束时检查结构。纯讨论可能不会形成改动批次。 | 即时捕获改动结构时，按权限检查保存后的结构。批末可以沿用范围相同且没有后续改动的结果。 |

任务 owner 保存可继续工作的当前状态。已执行的动作保留历史证据。受新目标影响的待办和达成判断需要再核对，保护规则在获准修改前继续有效。对超时、收据缺失或状态未同步的外部操作，是否可以重试取决于权威结果或实际有效的同一操作去重。两种格式沿用已有路径和正文，无需迁移或新增任务账本。

## 讨论与取舍

Gemini 4 Neon 经 Antigravity 以 `gemini-4-neon-xhigh` 请求执行两轮。原生回执返回 `gemini-4-neon`，分别对应会话 `0fee2376-c5ff-4af1-ad31-263db59a4898` 和 `477f942b-84fe-445c-95d9-ab398136b47d`。首轮断流后继续并返回完整评审。它识别了格式 4 的撤回检查断点和纯讨论后的结构检查缺口，也要求变更目标时审视相关保护及无法确认的外部效果。

Claude Code 的初次长题面未返回正文，终止后用冻结原文和 5.9 实测反例重新讨论。成功回执来自 `claude-opus-5-5`，会话 `dfc83214-c921-4e80-8bc1-7ece34bad51d`。它追溯了偏好误升格与补录候选规则的措辞，建议只复核依赖被替换条款的计划、方法和证据。两种讨论模型按本轮用户指定调用，常规验证仍使用获准的廉价模型。

实现采用了两个评审都支持的授权 owner 和窄范围复核方案。修改普通、可逆的任务计划沿用既有授权。真实受保护的冲突仍走偏离审查。对效果未知的动作保留经证实的同一操作去重路径。讨论中的跨项目偏好汇总、旧规则批量重新分类和宿主调度都需要各自的授权、接口和证据。

## 可观察结果

对照使用同一批合成任务与官方安装流程。每个会话均为独立的 Codex 进程和隔离的会话目录，读取正式安装的技能。接续阶段继承工作区文件，原会话和回复不随之传递。原生验证模型为 GPT-6.1 Terra，medium。协调者按文件变更、工具事件及交付结果核对，以下每臂每路径各一次。

| 路径 | 5.9 | 5.10 候选 |
| --- | --- | --- |
| 格式 4，暂停回调试验并修改内部交接偏好 | 保存目标和方法。将 “I prefer” 加入 `confirmed` 登记，额外修改了用户本次授权文件之外的入口。 | 只改任务记录和支持指南。保留原发布规则，记录内部表格偏好和合作方需要正文的例外。 |
| 格式 4，新会话接续回调试验 | 运行回放，记录本地结果，保留超时投递的未知状态。 | 完成同样的本地回放和交接。报告同时指出重开数据库连接不能证明执行到一半时的工作进程重启，完整验收继续待证。 |
| 格式 5，暂停展览并设置内部交接偏好 | 保存偏好和暂停信息。误报应将偏好登记成不变量，称本轮没有入口写权限。 | 使用既有编辑指南和工作简报。没有误报不变量登记义务，保留对外叙述与现行核验方法。 |
| 格式 5，新会话接续展览 | 生成两列编辑交接，保留原件权限和待审说明。 | 生成两列交接。事实性使用继续需要录音核验，未批准的简化方法仍是建议，转交回执仍为未知。 |
| 相邻错字修改 | 只改目标文本。 | 只改目标文本。 |
| 格式 4，明确批准一条硬规则 | 写入确认规则，保留既有规则，运行结构检查。 | 同样写入确认规则并在本轮检查。两臂都报告了预先植入的断链。 |
| 格式 4，撤回原件保留，只读检查获准文档 | 识别旧 checker 不能按格式 4 限制读取，手动发现断锚点。 | 实际运行 `ssot-check.py SSOT/README.md --owners ../docs/support.md`，返回预置的断锚点，不读取原件正文。报告列出排除范围，所有文件未改。 |
| 单次改用正文，保留已有表格偏好 | 返回一段正文，所有文件未改。 | 返回一段正文，所有文件未改。 |
| 普通只读咨询，核对发布权限 | 找到发布负责人，说清本地验证范围，所有文件未改。 | 同样回答并保持所有文件原样。 |

主要配对冻结于发布前的候选。单次覆盖与普通咨询使用随后统一了收尾时点和措辞的版本。独立 checker 回归监听真实文件打开事件。全量调用会打开撤回原件，也会发现未路由 Markdown 内的断链。选定入口和指南的调用保留授权文档的锚点检查，未打开两个被排除的 Markdown 文件。对未直接链接的选择，返回错误且不打开该文件。相同断言在旧 checker 上因格式 4 被拒绝而失败。格式 5 的受限读回归仍通过。

两个版本在测试中均能接续部分典型任务。观察到的改善是少写了一个不应修改的入口，消除了错误的登记义务，并让格式 4 的受限检查可以使用同一机械工具。原生运行的字节数和耗时有升有降。受限审查候选还主动阅读了 checker 源码。一次配对不足以推断日常成本或长期恢复成功率。交接中的投递和档案请求为合成状态，未调用真实外部系统。

## 下一轮证据

优先从真实多阶段工作选两项可用的案例。一项在更改目标后保留原方法中仍有效的部分，由新会话完成实际交付。另一项同时有任务级偏好覆盖、仍适用的硬规则、只读范围及跨工具来源撤回。记录无关任务的读写成本、未确认效果的处置和权限回归，用观察决定是否需要更明确的接续示例或宿主能力。本轮没有升级现有消费者安装，也没有验证真实外部系统的恢复、长周期记忆遗漏率或跨宿主撤回覆盖。
