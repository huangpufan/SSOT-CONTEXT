# 混合任务（单文档改写兼查另一文档）为何没有发布 5.16

**2026-11-24，Codex 对照试验后决定保留协议 5.15。** 5.15 实测中，Flash 在「更新费表并顺带查周六关门时间」任务上耗用了 243,443 输入 token，而解耦单文档改写的试验版仅用 56,557。本轮将「单文档已定正文改写」与「顺带只读其他已获准文档」单独解耦，保持纯查询路径不变，在官方安装器接线的隔离 Codex 沙箱内用 `gpt-6.1-terra`（`medium`）做了两轮共 31 个原生会话对照。第二轮 10 组配对全部通过质量与安全核验，但候选版合计输入从 825,285 升至 886,169（+7.4%），未达预设上线条件。[冻结计划、两轮候选补丁、逐次原生回执与成稿](../tests/benchmark/results/mixed-edit-study.json)

## 改了什么，以及第一轮暴露的守卫缺口

5.15 的双语入口模板与 Preflight 把单文档快捷改写写成「只改**这份**查询文档的现有正文（`confined there` / `that owner`）」。候选第一版只解耦这一句话，让同一请求附带其他已获准文档的只读查询时，仍可直接进入 `$ssot-closeout` 完成原地更新与回读，不改纯查询路由、保护规则、审批条件和跨文档依赖边界。

第一轮只跑完 3 个执行会话和 2 个冷接手就按早停规则暂停，但暴露了两项直接根因：

- **Closeout 缺少 `Otherwise` 守卫**：`amend5` 第一轮候选按预期跳过了 `ssot-preflight/SKILL.md`，直接进入 `ssot-closeout/SKILL.md`，却因第 14 行无条件写着 `Format 5 continues with context-spaces.md`（缺少 Preflight 第 19 行那样的 `Otherwise`），又顺手读入了 11.4 KB 的 `context-spaces.md`，单次输入从基线 69,505 升至 85,763（工具调用 3 → 6）。第二轮在 `ssot-closeout/SKILL.md` 第 12、14 行补上 `stop here` 与 `Otherwise`，随后四次格式 5 单文档改写全部不再误读 `context-spaces.md`。
- **偶发超时与观测窗口校准**：第一轮 `amend5` 第二次候选在工具输出返回后遇到 240 秒上游流无响应超时（退出码 124，保留 15,297 已知输入）。同时核查发现外层 `inotify` 监听把测试框架自身的前后快照也记成了文件打开。第二轮改用 `CLOCK_MONOTONIC` 精确框定 `codex` 进程窗口，并用空命令零打开、公开文件打开和受限文件打开三项校准通过后再开测。第一轮结果原样归档；因已审阅 `amend5`，第二轮将其标为开发证据，其余七类任务均为首次独立运行。

## 真正决定 Codex 成本的机制

把命令轨迹和原生 `token_usage_record` 对齐后，这组数据澄清了三个此前靠单宿主直觉看不清的事实：

1. **5.15 的 243k 飙升不是 Codex 上的普遍瓶颈。** 此前 Flash 在 `amend` 跑出 19 次工具调用并反复运行 `ssot-check.py`；在 Codex `gpt-6.1-terra` 上，现行 5.15 对 `amend5` 本身只用 5–7 次工具（80.8k–93.3k），对中文开发仓库 `dev4_mixed_zh` 甚至两次都直接走 Closeout（66.0k–66.3k，仅比纯文档 61.5k 高约 4.6k），全程零次多余的检查器运行。
2. **在 Codex 上，每多一轮 API 往返重播约 1.7 万缓存输入，盖过了少读协议文件的收益。** 候选第二版确实把 10 组配对中单次 API 请求的平均输入从 17,559 降到 17,042，也把 Preflight 加载次数从 5 降到 3、`context-spaces.md` 从 4 降到 2，在同为 5 轮往返的 `amend5` r2（-11,484）和 `mixed_restricted`（-8,392）上如期省了钱。但 10 组总 API 往返反而从 47 升到 52（+5 轮），直接吃掉全部节省并倒亏 60,884 输入。
3. **放宽适配器快捷改写措辞会诱发受保护任务的先读后退。** `dev4_protected` 的用户请求表面上像「改一份文档兼查另一份文档」。候选适配器让模型先加载 `ssot-closeout/SKILL.md`，读到 `SSOT/README.md` 里的 `INV-01` 才回退去读 `ssot-preflight/SKILL.md` 及相关参考，5 轮往返变成 7 轮（+34,559）。这证明在入口里放宽直达 Closeout 的措辞存在真实的回退代价。

## 裁决与下一步启示

依据冻结的上线门槛（要求四次主混合任务全部降本且 10 组聚合降本、零回归），**本轮保留 5.15，不发布 5.16**。两轮共 31 个原生会话（30 个正常完成、1 个 240 秒超时），合计 2,182,575 输入（缓存 1,959,040、未缓存 223,535）、15,844 输出、144 次工具调用、129 次原生 API 请求、耗时 909.9 秒；宿主为 Codex CLI `0.171.0`，实际返回模型均为 `gpt-6.1-terra`，推理档位 `medium`。完整两轮冻结现场与原生日志（已剔除 `codex-home` 与 `auth.json`）保存在本机私有归档 `mixed-edit-36c28da-20261124.tar.gz`，SHA-256 记于[结果文件](../tests/benchmark/results/mixed-edit-study.json)。

这组结果直接修正了后续降本的优先次序：与其继续放宽适配器把更多请求提前导向 Closeout（容易在受保护或跨 owner 任务上造成先读后退），不如优先探索两类更直接的改动：一是单独验证 `ssot-closeout/SKILL.md` 第 14 行补 `Otherwise` 的孤立收益（不改适配器触发条件，不诱发回退），二是压缩常驻与高频热读路径的体积与不必要串行往返（如把 `memory-model.md` 中仅用于建库/迁移的规则挖掘和旧布局章节下沉，以及研究如何减少独立文件读取的串行轮次）。若要专门针对 Flash 的 243k 混合改价失控做修复，也应在 DSH Flash 上另立独立对照，而不能由单一宿主外推。
