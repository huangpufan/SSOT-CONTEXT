# 拆分热读参考文档为何同样没有发布 5.16

**2026-11-24，两轮 Codex 对照试验后继续保留协议 5.15。** 上一轮[混合任务对照](2026-11-24-mixed-edit-study.md)排除了在入口模板放宽单文档快捷改写触发条件的方向，并提示两条更低风险的候选：把热读参考文档 `memory-model.md`（13.9 KB）和 `context-spaces.md`（11.4 KB）中非日常预检章节原文下沉到按需文件，同时补齐 `ssot-closeout/SKILL.md` 第 14 行的 `Otherwise` 守卫。本轮在 Codex CLI `0.171.0`（`gpt-6.1-terra`，`medium`）上跑完两轮共 38 个完整原生会话（42 轮，含官方 Parcel desk 编码基准、双轮热刷新、受保护规则、偏好采集、未登记代码保护与格式 5 搭建冲突）。第二轮 12 组配对全部通过质量与安全校验且零跳读回归，但 12 组总输入从 1,519,311 变为 1,524,740（+0.36%），未达预设上线门槛。[两轮候选规格、逐次原生回执与成稿](../tests/benchmark/results/hotpath-split-study.json)

## 第一轮：过度拆分交叉引用章节会诱发确定性跳读

候选第一版把 `memory-model.md` 中三块章节原文移至 `memory-admission.md`（第 2 节「存什么与目标/偏好」、第 3 节「人工决定证据」、第 5 节「从代码恢复规则」），把文件从 13,934 字节压到 8,616 字节（-38.2%），同时把 `context-spaces.md` 中旧版兼容、搭建进度与 Doctor 段落移至 `context-space-setup.md`（11,382 → 8,286 字节，-27.2%），并在 `ssot-closeout/SKILL.md` 补上 `stop here` 与 `Otherwise`。全部 58 项结构与现有预算检查零扩容通过。

第一轮完成全部 14 个格式 4 会话（7 组配对：基线 1,083,107 vs 候选 v1 981,841）后，因夹具遗漏 `--skip-git-repo-check` 在无 Git 的格式 5 场景零 token 中止（且格式 4 阶段未开启 `installed_mode=True` 自动注入 `AGENTS.md`）。但这 14 份轨迹已经清晰暴露了一项真实设计缺陷：`Human-decision evidence` 被 12 处协议链接（含 `protection-departure.md` 与 `ssot-preflight/SKILL.md`），移出 `memory-model.md` 后，**两次 `dev4_protected` 对照均在读完 `protection-departure.md` 后额外多花 1 轮 API 往返去开 `memory-admission.md`**（往返 5 → 6，输入分别增加 +14,457 与 +18,164），而且全部 7 个格式 4 候选会话依然全部读入了 `memory-admission.md`。第一轮数据原样归档，不并入第二轮裁决。

## 机制结论：在 Codex 上，往返次数比 3 KB 文件拆分大一个数量级

1. **按需拆分做到零误读、零跳读是可行的。** 候选 v2 中，`durable-storage.md` 在全部 12 个会话中加载次数为 **0/12**，`context-space-setup.md` 仅在真正需要它的 `format5_setup_continue` 加载 **1/12** 且未增加往返（同为 4 轮、省 2,992 输入）；在往返数相同且读了 `memory-model.md` 的配对上（`parcel_routed` r2、两次 `dev4_protected`、`format5_setup_continue`），稳定兑现了 -2,992 到 -6,585 输入的缩容收益。
2. **但 3 KB（约 650 token）的体积收益，比单次 API 往返波动小 5 到 10 倍。** 在 Codex `gpt-6.1-terra` 上，单次 API 往返平均携带 **19,731** 输入 token。最典型的反证是 `dev4_capture_pref`：基线和候选都只读了 `ssot-closeout/SKILL.md` 和 `decision-capture.md`（双方连 `memory-model.md` 和 `durable-storage.md` 都没碰），仅因基线把「读技能 + 读入口」「改文件 + 回读」合批为 4 轮（68,409），而候选逐个串行拆成 6 轮（102,751），同一路径就拉开 **34,342 token** 的差距——直接抵消了全部热路径缩容收益。
3. **因此，不值得为了约 0.3–1.6% 的噪声级净差，把 `skills/ssot-preflight/references/` 再裂出两份新参考文档。** 依据冻结门槛（要求全部 12 组总输入与未缓存输入双降、且冷反例退化不超过 5%），本轮**保留协议 5.15**；`ssot-closeout/SKILL.md` 第 14 行补 `Otherwise` 的 3 词小修则留待下一项具备实质收益的协议版本一并合入，不单独升版本号。

## 总量账目、证据边界与下一步方向

两轮 38 个完整原生会话（42 轮，Codex CLI `0.171.0`，实际返回模型均为 `gpt-6.1-terra`，推理档位 `medium`）合计消耗 5,108,999 输入（缓存 4,609,664、未缓存 499,335）、41,125 输出、256 次 API 往返、214 次工具调用、耗时 1,411.1 秒；另有第一轮 2 个格式 5 会话因缺少 `--skip-git-repo-check` 在 0.4 秒、0 token 处中止。完整两轮冻结现场与原生日志（已剔除 `codex-home`、`probes` 与凭据文件）保存在本机私有归档 `hotpath-split-c240b51-20261124.tar.gz`，SHA-256 记于[结果文件](../tests/benchmark/results/hotpath-split-study.json)。本结果仅覆盖 Codex + `gpt-6.1-terra`（`medium`）及每题 1–2 次重复，不能直接外推至无提示词缓存或系统前缀显著更小的宿主。

连续两轮共 69 个 Codex 原生会话已经把真正的大头钉死：**单靠微调入口触发词或把参考文档再拆细 3 KB，收益都落在 Codex 单次往返波动（±17k–34k）之内；真正能带来 15–30% 级稳定降本的杠杆，是在不破坏「先查权限再读内容」前提下减少可避免的串行 API 往返**——例如在 `ssot-closeout/SKILL.md` 明确「确认权限后的同批读取合批，以及单文件写入后可在同一验证步骤中重读落盘文本完成回读」，避免单文档改写白白拆出 6 轮（98k）而非 4 轮（66k）。
