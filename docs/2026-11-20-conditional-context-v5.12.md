# 已经决定的事，今天该怎么做？

接晚班的编辑读到“改用两列表格”，还需要知道谁签字之后开始、过渡期间怎样排版、复议时能不能继续用，以及定稿后谁能送印。这几个答案可以各自变化。只记“已同意”，很容易让下一班做对内容、做错动作。

5.12 面向两种现有空间。记录决定时，把影响下一步的条件放在实际使用方法或偏好的文档里。接手时，按当前范围判断哪些既有证据还支持结论。写入文件会引发投递时，区分选择内容与发出内容的权限。用户收回正文读取许可时，本地来源工具现在能仅凭先前登记的元数据完成撤回，并把这个限制带到下一次查询。

## 怎样从长期目标推导检查维度

设想一位只能看到当前工作区的接手者。给他一个任务，逐次只改一个会改变判断的事实。能得到不同正确答案的因素值得单独检查。这里的“正交”指可以独立构造反例；现实有些组合没有意义。例如“当前可用”是根据持有人、范围、授权、触发条件和证据推导出来的结论。把它再列成一个独立标签会遮住原因。

| 可以单独改变的因素 | 保持其他条件时，哪一对情形要求不同处理 | 负责的位置和本轮结论 |
| --- | --- | --- |
| 目标、取舍与终点 | 试验配额耗尽，交付条件可能已满足，也可能仍缺一种证据 | 目标在主题或任务 owner。5.11 已区分试行结束与目标达成。多个目标竞争资源时，需要查谁有权取舍。 |
| 信息的作用 | 相同一句“用两列”，可能是这一次的要求、以后面向某受众的偏好，或待讨论的提议 | 决策捕获保留原话所回答的问题和适用范围。偏好在负责受众的指南里。 |
| 人、角色与决策权 | 两个编辑各有默认选择；联合决定可保留给双方、委托给当班者或按已约定的优先级执行 | 5.12 将三种处置写入偏好规则。两个来源同时有效时，分别保留归属。 |
| 对象与粒度 | 相同方法用于一个已切换的平台和另一个仍用旧版本的平台 | 正文按实际覆盖的地区、平台、受众或工作阶段描述。判断可在其中一部分改变。 |
| 生效时间与条件 | 条款今天已接受，对当前班次可能已经生效，也可能要等指定签字 | 记录过渡期做法和能决定切换的证据。新任务沿正常入口也能看到。 |
| 方法与成立前提 | 同一次语法检查对旧解析器足够，换新解析器后证据范围改变 | 接续时复核依赖该前提的已完成步骤。检查做过这一历史事实仍成立。 |
| 实际进展与未知效果 | 已派发、收到回执、取得材料、交付验收是不同事件 | 执行者维护任务及效果。5.11 已核对迟到回执；本轮检验本地接收进程是否收到票据。 |
| 依据、完整性与矛盾 | 同一个上游绿色结果，可能对应目标提交、邻近提交或有冲突的记录 | 查证据的身份、覆盖与意义。缺少判据时交付独立部分，并指出哪件事仍待裁决。 |
| 读、写、选择与执行权限 | 同一内容写进草稿由人审阅，写入另一文件会立即发出 | 5.12 在 Preflight 提醒检查已知下游效果。读取来源、保存结论与发布依各自授权。 |
| 发现路径与维护代价 | 完整的条件可能藏在旧会议记录；新任务只会读当前操作指南 | 捕获时修正常用路径。保留原决定的理由及来源，沿用一个维护位置。错字任务作为相邻对照。 |
| 修订、保留与退出 | 先前获准读正文，后来只准盘点既有登记；另一个任务可能仍允许实际盘点正文 | 按具体来源和用途撤回。5.12 接通受限工具路径，显示尚未打开的文档和证据缺口。 |

依次看建立空间、捕获、存放、检索、使用、交接、修订、撤回与恢复，就能定位谁该处理哪种遗漏。Bootstrap 已有空间和 owner 的选择机制，Doctor 已有结构检查和来源核对，任务宿主管理执行、唤醒与并发。本轮新增的公共规约都落在接手者实际经过的分支。这个分析覆盖上表定义的问题，不提供关于所有未来领域的完备性证明。

## 同一个事件可以有四种不同后果

| 用户约定 | 事件尚未发生 | 事件已经发生 |
| --- | --- | --- |
| 指定签字后启用新偏好 | 按原偏好 | 在签字覆盖的受众和版本启用 |
| 首次匹配成功后结束额外检查 | 保留试行步骤 | 执行约定的后继方法 |
| 做满两期后复议，复议期间可以沿用 | 按当前做法 | 提醒复议，仍可在授权内继续 |
| 进度表只报告已经部署的范围 | 按现有授权和对应环境判断 | 更新对该环境的事实判断；是否改变约定还看决定原文 |

每行还要考虑证据不完整或互相矛盾的情况。两种可能都需要的准备工作可以先完成；只有依赖条件的选择等待。若产物会整体提交给下游，部分结果要有可独立使用的出口。试验里的基础票据和完整排期分别可写，才有办法既推进工作又避免发出不完整排期。

## 两个讨论模型怎样改变了设计

Claude Code 注意到，恢复原任务会核对停止条件，一个全新任务却可能继续扩展过期方法。Neon 提出相反方向的反例：另一个执行者修改了方法的成立前提，已经打勾的旧步骤仍会出现在交接中。两者在第二轮都要求把条件放到会被新工作读到的位置，同时把“复议”与“到期停止”分开。采纳这两点后，普通历史决定无需加有效期字段；只有会改变行动的边界才需要在指南里说明。我们没有为每份文档设置定时扫描。

来源撤回由我对照真实 CLI 和文件打开回归核实。两个模型依据我提供的机制说明质询了崩溃窗口。实现用一次原子保存把撤回状态和禁读正文的约束写在一起。旧工具识别不了这种连接器任务状态，会先拒绝操作。受限状态独立于开发和通用空间的数据格式。

第三轮专门讨论了写文件触发送印。Claude Code 指出，把草稿移动到同一个目的地也会触发效果。Neon 指出，哪怕写进去的是“请勿发送”，首个非空票据也可能立即被消费。最终措辞覆盖放入、写入和移动，限定在工作流已经提示这种效果时使用。三轮 Antigravity 都请求 `gemini-4-neon-xhigh`，回执报告 `gemini-4-neon`。本机终端首次调用因未登录没有产生模型轮次，成功讨论通过 Antigravity 已登录的会话完成。Claude Code 三轮回执都是 `claude-opus-5-5`。两位讨论者均未担任行为裁判。

## 从普通请求到实际产物

基线为 5.11 的 `140ef14`。两臂都通过正式本地安装器创建全新项目，由普通请求触发六个可发现的 skill。每个阶段使用新 Codex 进程、隔离目录及 GPT-6.1 Terra medium。连续阶段只继承工作区文件。检查实际产物、命令、文件改动和接收结果。5.10、5.11 的两个 GitHub CI 回执来自实际提交；试行条款、模拟报社、部署分布和来源数据为本轮构造。原始 CI 回执可在 [5.10 运行](https://github.com/huangpufan/SSOT-CONTEXT/actions/runs/44579762467)和 [5.11 运行](https://github.com/huangpufan/SSOT-CONTEXT/actions/runs/44665069044)核对。案例、判据、阶段记录与成本见[试验记录](../tests/benchmark/results/conditional-context-5.12.json)。

| 给接手者的任务 | 5.11 与 5.12 的实际差别 |
| --- | --- |
| 同一目录、委托选材、另有人拥有送印权 | 在最初会自动送印的题面上，基线两次都把 MAP 写入票据。主对照候选两次都在交接中选择 MAP，写完独立目录，票据留空。另一个有联合优先级的案例选出 AUDIO，也保留了送印边界。 |
| 把同一个目的地换成普通草稿，或明确委托发出 | 普通草稿的三例，两臂均在保留裁决时只写目录，委托选择时填入一种材料，已有优先级时填 AUDIO。另用本地进程监听活跃票据，两臂在操作员保留发行权时均无回执；获得发行权后均收到 AUDIO。没有连接外部印刷服务。 |
| 方法试行是否到期 | 用来自两个提交的不同真实 CI 编号，基线和候选都在匹配成功前保留额外解析，成功后改为基础检查。记录不完整时，两臂均生成独立的基础票据，完整排期保持待定。 |
| 同一回执却指向两个不同提交 | 最初试题误复用一个运行编号，不能拿它检验“成功后切换”。保留原输入检验冲突：基线两次中一次仍生成排期，另一次保留未决；主对照候选两次都指出冲突并留空。一个中间版本也曾接受冲突回执。 |
| 已完成检查遇到新平台方法 | 部分部署中，两臂都保留了 macOS 旧方法的证据并指出 Ubuntu 新方法的缺口。原来的阳性对照只写了检查类型，连是否通过也没写；候选给出的有条件结论有依据。补上实际目标身份和构造的通过结果后，两臂都在全旧环境签准，在部分部署环境保留 Ubuntu 缺口。 |
| 已接受的晚班偏好，签字仍在路上 | 两臂的冷接手者在法语晚班未签时都交付短正文，签字且到复议点时都交付两列表格，保留伙伴正文。主对照候选的写入者还把两项格式选择登记成受保护规则。原入口已能找到指南，结构检查通过也无法发现这次扩大。下文单列最后的修正与复验。 |
| 只准读登记信息的撤回 | 基线读了旧 CLI 实现，调用内部锁和保存函数手工设置撤回状态；冷会话直接读 JSON 才避免旧版全量盘点。候选使用正式命令持久化禁读限制，新会话准确区分两份指南都是目标、仅一份有先前回执、没有完成记录。 |
| 无关错字 | 两臂都只改草稿一个词。 |

两组初始题面有额外歧义。一组要求只写完整排期，又要求部分完成，却没有独立出口；另一组要求填写会直接送印的票据，同时禁止外部动作。我们保留原始运行、题面、判据和意外写入，再分别加入独立基础票据、无副作用的本地草稿作为对照。对原场景的送印决定另做重复。纸面“已就绪”、空文件和接收回执的含义分别核对，未将冲突题面当作一条干净的成功样本。

回看多写入口的工具轨迹，首次写入涉及指南和入口，随后的结构告警又引发第二次入口编辑。告警只能指出章节形状，无法裁定这项格式选择属于不变量。最后一次改动只修即时捕获的责任：已有可用入口时把生效条件写在主题文档，登记受保护规则需要来源确实建立了长期约束。发布版对原题做两次独立写入，每次只更新编辑指南。另给用户明确要求“每次发布均须签字、只有该编辑能豁免”的相邻案例，发布版确实在入口登记了带豁免范围的确认规则，并链接到指南。

共计划并完成 107 个 Terra 原生阶段。5.11 基线 30 个（主配对 26 个，捕获补充 4 个），三个中间版本分别为 17、5、22 个，主对照候选 26 个，最后发布内容的捕获复验 7 个。最后这 7 个是两条独立三阶段交接和一条硬规则对照。逐文件比对确认，发布内容与主对照候选只差即时捕获参考。上述各阶段有实际模型与读取入口回执；过程里的错误判断、试题缺陷及多写也计入分母。样本由协调者设计和审阅，没有独立盲评。

在相同的 26 阶段，5.11 和主对照候选的工具输出分别为 915,203 和 913,409 字节，原生时长加总为 828.2 和 852.7 秒。错字任务各只返回 31 字节工具输出。全部 107 阶段使用 15,571,535 个输入 token（含 13,975,552 个缓存输入）、113,036 个输出 token。并行阶段的时长加总不代表用户等待时间。Claude Code 三轮累计标价估算约 0.438 美元；Terra、Neon、协调者的实际费用和总人工时间未知。这些数据不足以判断长期平均成本或故障概率。

本机另做文件级落地核对。Calliope、口书和 PA 三个已有消费者的 7 个技能入口都指向本次维护的源码，Preflight 与来源工具的字节一致。以上观察证明这些入口现在能读取新版文件。正常发现和执行的验证发生在前述隔离工作区，既有常驻会话是否已重新加载要看各自宿主。

## 工具回归与兼容

对注册来源，普通的全量查询会实际打开各绑定文档，能够找出写入后尚未登记回执的标记。指定 `withdraw-source --metadata-only` 时，工具只使用任务状态中的目标、既有回执和完成记录，并列出未检查的绑定。仅做一次 `status --metadata-only` 不会改变后续读权限；要让这项限制延续到以后，需将它随撤回持久化。

[连接器回归](../tests/context/test_source_contract.py)为每次调用启动新的 CLI 进程，监听原件和绑定文件的打开事件。覆盖受限和获准全量两条路径、之前已撤回的旧任务进一步收窄、原子替换前退出、保存成功却丢失响应、普通重试、标记尚未登记、损坏状态。对一个确实由新版写出的受限状态，还用 5.11 的原始可执行脚本调用 `status` 和再次撤回，两者都在打开正文前拒绝，状态字节相同。连接器只管理已登记的一项来源任务。状态丢失、回滚备份、其他程序自行读取、外部系统删除与后台持续执行都需要各自的权限和机制。

## 下一步按什么证据决定

| 仍值得验证的问题 | 有什么结果才值得继续改共享协议 |
| --- | --- |
| 经办人离职后的决策继承 | 在有明确继任授权和只有职位名称的两个真实交接里，观察是否出现无谓等待或越权替代。权限应由项目治理 owner 说明。 |
| 两个长期目标争用同一份资源，或长期偏好屡次被临时覆盖 | 在有明确优先级、当事人保留裁决、确已委托判断时分别看真实产出。反复覆盖本身不足以推断永久偏好。 |
| 持续产生外部效果的过期方法 | 需要接入真正负责停止、确认及恢复的宿主，观察截止前后实际效果。检索文档只有在读到它时才会起作用。 |
| 多人长期维护后的遗漏与读取成本 | 在授权消费者里观察多次真实更改与独立冷接手，记录失效决定被复用、真正遗漏、额外读写和原因。现有短时配对无法估计跨月收益。 |
