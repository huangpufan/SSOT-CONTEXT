# 目标变化后，下一班该做什么

一个任务可以同时有三件都是真的事：用户已经撤回目标，执行者昨天已经发出请求，今天才收到送达回执。后来的会话需要据此写出准确的交接，并继续仍有授权的工作。把三件事合成一句“已取消”，会丢掉已经发生的事实。反过来，把“已送达”当成目标仍然有效，又会重新启动用户已经叫停的工作。

5.11 保留了 5.10 的入口、文档归属和两种数据格式。改动集中在两个时刻：一个选择刚刚变化、可能使已有的下一步失效时，以及接手者将要依据旧记录实际行动时。

## 长期维护需要回答哪些问题

| 冷接手者的问题 | 谁能回答，什么时候需要更新 |
| --- | --- |
| 现在追求什么，怎样才算达成或可以停止？ | 主题文档保存持久目标和约定，任务记录保存这次工作的达成条件。接手时根据当前范围和相应证据判断。明确约定且证据齐备的条件可以直接应用，需要人判断的结果仍待接受。 |
| 方法还适用吗，失败过的做法值得重试吗？ | 方法由原指南或试行决定维护。任务交接保留会影响下一步的失败条件和证据。试行次数用完后可以交付已有发现，目标是否实现仍要判断；扩大试行需要相应授权。 |
| 用户在讨论中改了方向，正在做的事会怎样？ | 即时捕获处理已知、直接受影响的下一步。能改自己的任务记录就纠正旧指示；另一执行者持有任务时，改它会查阅的获准文档，说明缺失的路径。原执行者负责核对已经发出的动作及迟到回执。 |
| “这次这样写”和“以后我偏好这样写”分别影响什么？ | 本次要求作用于本次交付。明确建立的长期偏好进入相应对象的既有指南，保留持有人、作用域和例外。描述团队平时做什么，还需要区分谁实际决定了未来的做法。 |
| 能否从另一个项目任务取材并代它结案？ | 报告可以说明源记录与审定结果有出入。改变源任务状态需要执行权限。这条界限放在 Closeout 入口，因为收尾时整理文档也可能造成越界写入。 |
| 怎样检查新交接文档，又不打开索引旁边的受限原件？ | Doctor 的 `--owners` 接受完整且显式选定的 Markdown 路径。给出入口、获准的索引和任务卡即可核对卡中的锚点。未获准的材料留在选择范围外。 |

从 Bootstrap 建立入口到 Doctor 复核，实际需要的是让后继任务找得到负责的文档。新主题确实没有访问路径时才补链接。正常启动仍沿用已有索引；每个项目增加一份目标总表、给每项工作添加固定状态字段，或者定期扫描所有任务，都会引入第二个要维护的地方。此次保留了 Bootstrap 的设置流程、已有决策的出处及局部替代规则、普通任务的读取入口。长期偏好的跨项目汇总、宿主主动唤醒执行者和跨系统取消操作需要各自的权限与接口。

## 两轮设计质询

Antigravity 实际接受了 `gemini-4-neon-xhigh`，两轮回执的响应型号都是 `gemini-4-neon`。Claude Code 两轮回执均为 `claude-opus-5-5`。首轮分别给两者相同的 5.10 原文，第二轮在各自原会话里质询两份建议及其反例。设计讨论与行为试验独立计数。

Neon 指出了纯讨论后残留旧下一步的窗口。它随后用一个反例修正了“捕获时改掉所有相关任务”的想法：若目标已收窄，旧目标的签字可能随后到达，而任务正在别处运行。它建议恢复时核对签字所对应的目标和范围。Claude Code 起初建议达成停止条件后等待人工确认，质询后将它收窄到仍需要价值判断的情形；它也撤回了每次试行都要沉淀一条方法记录的建议。实现采用了按所有权修正已知依赖、由执行者核对回执的办法。到达试行上限可以限制下一步，过去那次试行的授权和历史结论仍按原样保留。模型建议的优先级没有直接写成通用规则。

## 怎样验证

以 5.10 的 `fb77efa` 为基线。每条路径都从该臂的正式本地安装器开始，由普通用户请求进入，核对六个 skill 实际可发现。每轮使用独立的 Codex 进程、会话目录和中等推理的 GPT-6.1 Terra。多轮只传工作区文件。案例和裁判在相应对照前冻结，核对文件内容、实际命令、回执和写入范围。研究结案和单次会议使用本仓库 D07/D08 的真实审定状态及回执哈希，围绕它们的工作区、策展任务和外部状态是构造的。原始研究的早期失败评级一并保留。[原研究记录](../tests/context/trials-delegated-decisions.md)

检查器回归先对 5.10 运行。开发格式和通用格式都把合法任务卡报成“必须从入口直接链接”，漏报卡中故意放置的坏锚点。修复后，两种格式均在指定索引和任务卡时指出锚点；单独指定任务卡会被拒绝。修好锚点后通过。测试监听文件打开事件，验证两种格式都没有读取索引旁的受限原件；漏选索引时也没有打开索引和任务卡。索引与任务卡互链的情况也在同一回归中。普通全量检查保留原有遍历范围。[检查器回归](../tests/test-ssot-check.py)

## 对照看到了什么

| 用户路径 | 5.10 基线 | 5.11 发布候选 |
| --- | --- | --- |
| 继续有明确结案条件的来源归属研究 | 核对两份审定回执，关闭原研究，保留 D08 早期误判，没有再次排队。 | 同样只更新原任务。不因早期失败再跑一次，也没有把这两次观察推广到其他模型。 |
| 纯讨论修改重启验收，再由新会话交付报告 | 保存新标准，纠正任务卡中失效的下一步。下班报告承认重复投递只记一次，实际进程重启仍未验证。 | 保留同样的结论和单次试行上限。上一轮重开数据库连接的证据继续支持它确实观察到的部分。 |
| 署名回执缺失／已到，两份策展简报只差这项事实 | 缺签时交付已清材料；有签时两项均进简报。两次也都更新了任务卡。 | 两种条件下都只改内部简报。前台显示绿色时继续等待签字；签字齐备且目标仍生效时，简报实际使用两份材料。 |
| 展览撤回公开文案，档案签字仍有效 | 第一轮正确保存撤回。冷接手把撤回说明写进原本空白待用的公开文案文件，同时完成内部简报。 | 第一轮保存更正。冷接手保留公开文件原样，完成内部简报。任务卡写清目标已撤回，但最后口头回复又写了“public caption remains pending”，容易混淆占位文件和真实任务。 |
| 单次会议用两列，团队平时读正文 | 只写会议报告。 | 发布候选的三次独立执行都只写会议报告。中间候选两次多写了源研究任务，其中一次还把对团队习惯的描述保存成长期偏好。 |
| 编辑明确建立内部表格偏好，伙伴仍用正文 | 首轮写入既有编辑指南，新会话按偏好交付两列简报。 | 两轮分别只改指南和简报。面向合作方的例外、两条材料不同的允许用途和试行尚待接受的状态都保留。 |
| 另一执行者持有任务，回执晚于目标撤回 | 当轮保留未知，下一班读到 O42 已送达，明确材料尚未获得，南区摘要仍获准。 | 撤回时不改执行者的队列和日记。一个独立本机进程随后给 O42 写入送达回执。新会话交付的文件区分了请求已送达、录音未取得、原目标已撤回，并保留南区工作。 |
| 只检查工作索引下任务卡的证据链接 | 对入口和索引的机械检查通过，接手者手动发现卡中锚点缺失，并说明机械检查未覆盖任务卡。 | 接手者通过正式安装的 Doctor 同时选中索引和卡，检查器直接返回缺失锚点。两臂均给出了正确诊断，所有工作文件均未改动。 |

捕获任务的关闭和读取这个任务给会议写报告，需要不同的权限。中间候选的一次会议任务通过后又复发。工具轨迹显示，多写的会话先读了 Closeout 入口，把历史检查点视为必须修复的过时文档，却没有进入暂停与恢复参考。发布候选把“引用资料是否也能改变源任务状态”的判断放在两个格式共同经过的 Closeout 入口。额外的两次重复在运行前约定，两次都计入成本。这是针对复发路径的观察，小样本无法给出以后多写的概率。

策展案例只明确冻结了当班的任务卡。后继会话把“下一班”视为可以整理该卡的条件，因而这条路径只能检验撤回的公开产物是否被触碰，不能证明仍由他人独占的卡在解冻前一直完好。对仍由另一执行者持有的记录，另用队列和日记验证。真实分布式锁、多周项目的偏好召回率和遗忘率仍待独立证据。下一项值得观察的是实际跨周工作中，后继者能否先找到有权解释目标的那份记录，以及最后给人的答复是否准确区分旧占位符和当前意图。

## 分母、成本与复查入口

9 条不同的用户路径组成 13 个会话阶段。基线完成 13 个阶段，三份中间候选分别完成 11、13、13 个阶段，发布候选完成同一组 13 个阶段和 2 次单次会议复跑，总计 65 次原生会话。全部返回可核对的模型及用量回执。执行完成与正确性分别判断。除上述会议误写外，第一份候选还把“现场执行者当前持有队列”放进了入口的不变量小节；发布候选只更新决定与交接，没有把临时分工升级为长期规则。两次设计讨论各自有两轮，单独记账。

同样的 13 个阶段，5.10 的模型原生时长合计 519.1 秒，5.11 合计 461.5 秒。工具输出分别为 635,532 和 577,958 字节，其中含命令结果与协议正文。一次对照且各任务上下浮动，不足以推断长期节省。包括所有中间候选和重复在内，Terra 共使用 10,843,013 个输入 token（其中 9,601,408 个为缓存输入）和 84,875 个输出 token。Claude Code 会话的累计标价估算为 0.359 美元，Neon、Terra 的实际收费、协调者用量及总人工时间未知。
