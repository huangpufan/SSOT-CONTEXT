## Decision and acceptance

The benchmark should help a maintainer decide whether a proposed SSOT mechanism improves complete collaborator tasks at justified cost, and locate failures well enough to choose the next useful experiment. It must distinguish knowledge/authority correctness, task progress, upkeep/recovery, host/infrastructure limitations and observation gaps. A larger test count or a lower token total is insufficient.

Acceptance for the redesign:

- Calibration accepts genuinely successful and legitimate alternative outcomes, and rejects planted outcome violations, false persistence/completion claims and corrupted or incomplete evidence. Expected results come from task contracts, not from the candidate implementation or its final answer.
- The observer covers the authorized workspace independently of launch directory, retains actual artifact/model identities and failed/partial attempts, and does not confuse missing evidence with a pass. Subject isolation preserves existing authentication boundaries without exposing oracle material or sibling attempts.
- Representative paths are chosen by decisions the suite must support. Existing executable reading, capture, continuation, source-recovery, installation and non-trigger evidence should be reused where sound; additional scenarios need a demonstrated discrimination purpose. Synthetic limits remain explicit.
- Comparisons freeze inputs, bundles, harness and expected outcomes before calls; tuning observations and independent confirmation are distinguished. Quality comes before conditional cost comparisons; human intervention, rework and maintenance belong to the complete task where observable.
- An actual feedback cycle runs the improved benchmark, adjudicates its findings, implements justified SSOT improvements, and evaluates the resulting candidate plus relevant counterexamples. Rejected changes and remaining evidence gaps stay visible. Documentation, cleanup, local checks, independent review and ordinary commit/push/readback complete each accepted slice.

## First-principles design and adjudication

The maintained document is an intermediate artifact. The primary new outcome is whether an unrelated, fresh collaborator can act correctly from it. The cold-handoff lane therefore fixes the consumer instruction and tool view across treatments and changes only what the writer leaves behind. Reporting uses executable code in a development repository; the predeclared editorial confirmation uses a named format-5 entry without Git and a publishing configuration artifact. A seeded field prevents guessing from model priors. Each has a scoped correction and an independent boundary that must survive it.

The `plain` arm keeps identical factual documents, including their existing SSOT shape, and ordinary ownership/routing instructions, while removing skills and workflow wiring. It estimates the protocol's added effect on maintained documents. It is not a comparison against all forms of memory. The absent-decision and stale-decision consumers test a different question: whether missing or outdated handoff knowledge actually changes the outcome. Known owner boundaries belong to these fixtures, not to a universal prescribed directory layout.

CC independent analysis and cross-discussion used actual `claude-fable-5-1` and `claude-opus-5-5`. Their implementation reviews found useful defects; they also made claims that were withdrawn or rejected against code. The main coordinator owns adjudication. Accepted repairs include strict boolean/schema checks, a fresh function-probe marker, retaining parseable usage and summaries after receipt corruption, distinguishing unknown from wrong model, checking discovery in native sessions as well as prompt probes, classifying invalid owner transfers as quality failures, binding reviews and reports to bytes/types/modes, recovering a review/result interruption idempotently, and making calibration a prerequisite for comparable cost claims. A report cannot inherit a stale pass after its artifact changes. No security claim against deliberately malicious generated Python is made.

Rejected expansions include an overall score, arbitrary improvement thresholds, consensus as truth, removing protection rules after a few ties, deleting existing nearby regressions merely because they share an oracle, and automatic retries with best-of selection. Separate output roots retain changed or failed experiments; the report must name that history. Semantic review is required for standing/scope and completion claims in the handoff lane, not imposed on every executable reading outcome. The main maintainer authors and reviews these public fixtures; that is explicitly not independent semantic proof.

## Calibration history and current evidence

The observer smoke used the same 5.2 bundle in both reading-typo arms and actual Terra sessions. Both changed only the requested file, exposed the expected native model and had complete observations. It validates the recorder path, not a protocol performance difference. Later harness refinements required a new frozen cycle rather than replacing these artifacts.

Candidate and confirmation are frozen before any editorial native attempt. The proposed candidate removes only the duplicated unconditional memory-model link before preflight dispatch; it adds no duties and removes no protection, capture or freshness requirement. Its adoption still depends on native outcomes and a separate judgment of whether the simplification has value; a token difference alone will not decide it.
