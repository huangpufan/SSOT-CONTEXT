# Evolution review and unfinished work

This review asks which accepted directions still need work in the bundle itself. The starting point is `06d8056` (4.4), plus two uncommitted checker/test edits. Consumer adoption and new host integrations are separate projects: this review does not authorize migrating other repositories, publishing private conversation archives, or installing hooks. Historical limitations remain limitations unless new evidence observes the same outcome.

## Direction established by history

Version 2 accumulated governance without keeping facts current. [DESIGN.md](../DESIGN.md) records why version 3 removed completeness certification, ledgers and release-triggered consumer work. Versions 3.5–3.15 refined protection discovery and acceptance after real failures: recovering a rule must preserve its conditions and source, while implementation truth alone cannot establish human approval. Version 4 adds existing repository-local owners and immediate decision capture without moving every fact into SSOT. Versions 4.2–4.4 then reduce routine reading and measure complete tasks; 4.4 removes the dedicated reader after mixed results rather than preserving an extra interface without demonstrated value.

The resulting direction is small routed memory, preserved source and scope, and explicit uncertainty. More machinery is justified by a demonstrated failure and whole-task evidence, not by a desire to make every historical limitation disappear. [CONTRIBUTING.md](../CONTRIBUTING.md#changing-the-protocol) owns that admission standard.

## Checker findings and observed repair

The two starting alias regressions also pass against the unmodified 4.4 checker. They strengthen the identity test set but do not demonstrate a new alias defect. The uncommitted helper is removed: one shared entry inode cannot establish directory identity, entry order is unspecified, and returning a guessed root after a scan error would hide uncertainty. A controlled-order test using real hard-linked files makes that helper incorrectly select SSOT as the repository root; it fails against the preserved starting patch and passes without the helper. The original edits were preserved outside the repository before replacement. The resolver still allows system aliases above a worktree and prevents an internal symlink from selecting a foreign one.

An independent counterexample does expose a released defect. Under inherited `GIT_DIR`, `GIT_COMMON_DIR` or `GIT_OBJECT_DIRECTORY` pointing at a separate empty repository, the 4.4 checker returns PASS after a confirmed rule was changed without a new source. With foreign `GIT_WORK_TREE` (alone or with `GIT_DIR`), it rejects clean local memory as foreign. The regression ran against an exported HEAD checker and produced five failing subcases; both original alias tests passed in that same run. This is a history-selection failure, not a spelling problem.

The repair strips repository-routing environment variables once for every checker Git command. Each tested foreign environment now allows clean local memory and rejects the unauthorized change. Index and shallow-file neighbors also retain the expected result. Tests hash the repository before and after the command to check the read-only boundary. A shared-file counterexample additionally checks that a hard-linked README does not turn SSOT into a repository root. This does not change the CLI, output vocabulary, exit-code contract or protection policy.

Local Linux validation: 118 checker tests pass, ten benchmark self-tests pass without model calls, 107 installer checks and 48 bundle checks pass, ShellCheck and Python compilation pass, and `git diff --check` is clean. The starting unfinished patch exceeded the existing 48 KiB checker budget (49,817 bytes); the repaired checker is 48,687 bytes and fits without raising the budget or cutting unrelated rules. Exact-commit CI is a separate release observation. These mechanical results do not close the bootstrap/adoption or live decision-recovery gaps above.

## Installer replacement failure and authorized repair

Fault injection against `590977a` confirms the replacement gap in the inventory above. A successful temporary project-local Codex installation is marked as an old generation, then a second installation uses a temporary `mv` shim which reports failure only when promoting `ssot-preflight`. The installer returns 71; the old preflight directory is gone, the other five old skills remain, and staging is deleted. The injected diagnostic is checked before interpreting this result. An earlier probe used an absolute destination while the installer used a relative one and did not inject the fault; that non-reproduction is retained separately.

The proposed repair keeps old entries recoverable before replacement and rolls back on failure or cancellation, retaining backup locations if rollback itself fails. Validation must cover failure after earlier promotions, interruption, an unsuccessful rollback, success, language and companion ownership, plus a safe rerun. This is an installer implementation change outside this repository's current `AGENTS.md` allowlist (skill list, registry or fetching). In response to “允许本次修改安装器，修复备份与回滚”, the user explicitly answered “允许兄弟。” on 2026-11-10, then added “我给你后续推进的一切授权，你尽情做吧。” This authorizes the remaining implementation, validation, cleanup and commit/push work needed for this goal, including installer backup, failure/cancellation rollback and recovery handling. It does not turn this task authorization into an unrelated global policy edit. The user also asked “拉取一下远端推送记得”; fetch and fast-forward incorporated `146beb8` before implementation, and the remote is rechecked before pushing.

The success contract is per installation location: before commit, failed replacement restores the previous bundle and companion ownership; successful replacement has a complete new bundle with the chosen language; unrecoverable rollback or an untrappable process kill preserves backups and identifies recovery state instead of letting a rerun overwrite it. A location lock also prevents another install/upgrade/uninstall from mutating that same location while replacement is active. This is failure recovery, not atomic visibility to concurrent readers or an all-locations transaction. Ordinary CLI requests and consumer memory remain unchanged.

The [installer repair evidence](../tests/installer-recovery.md) covers that contract with eighteen executable fault/cancellation/recovery cases and the existing e2e suite. Previous entries are renamed to backups before promotion, errors and INT/TERM compensate, and incomplete compensation/SIGKILL retain recoverable state. A stopped attempt's controlled recovery is verified before retry; committed cleanup failures remain distinguished from failed replacement. A dangling unowned companion is protected, and literal-path recovery discovery works even after the primary skill is absent. The remote's duplicate unittest method is removed and a uniqueness check prevents recurrence; its 50 KiB budget remains while the inaccurate code-growth explanation is corrected.
