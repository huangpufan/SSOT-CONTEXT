# 当两个空间共用目录，或撤回许可时进程中断

一份长期维护的资料，至少要让下一位接手者知道该处理谁的事、什么仍然有效、谁能改变它，以及上次工作究竟做到哪一步。我们从 5.7 的六个 skill 和实际入口出发，沿发现、建立、读取、纠正、撤回、检查和接续走了一遍。5.8 修改了两个能用旧版复现的问题。开发仓库仍用格式 4，通用空间仍用格式 5。日常开发的前置阅读和独立审查门槛沿用 5.7。

## 两个入口放在一起，究竟要接着做谁的事

在同一目录里，野外采样有自己的入口和现场指南。博物馆用 `README.md` 和 `BOOTSTRAP.md` 管理借展，港务方用 `STATUS.md` 记录船只状态。5.7 的 Doctor 明明收到了采样入口，却提示继续博物馆的搭建，并建议提取有用内容后删除港务方的文件。只读试验里的 Agent 最终答对了，但它打开了旁支资料来排除误报。另一个受托继续采样搭建的 Agent 也做对了业务，却把旁支警告带进交付。

5.8 让未完成的入口链接自己的进度记录，记录注明入口、已同意的范围和下一步。原先明确约定的旧记录仍然可用。入口和记录发生冲突时，就现有授权无法决定该继续什么，保留文件并询问即可。Doctor 仍检查实际链接、直接关联文档和断链。对格式 5，文件名不再触发开发仓库的迁移清理建议。显式传入一个缺少格式标记或格式不受支持的文件时，检查在该入口报错，避免扩大到整个目录。[空间协议](../skills/ssot-preflight/references/context-spaces.md) · [检查器回归](../tests/test-ssot-check.py)

| 从用户入口执行的任务 | 文件和回答中观察到的结果 |
| --- | --- |
| 只审查采样空间 | 最终版本依据现场指南回答“离港前采样”，说明该入口未找到进度记录，工作区字节未变。有会话列出了目录文件名，未打开旁支业务文件。 |
| 继续具名进度文件，或继续旧版 `BOOTSTRAP.md` | 两条路径都把“低潮时”写进已有指南并保留“离港前”，随后移除本空间已完成的进度。另一次由用户明确指出未被入口链接的旧记录也顺利接续。 |
| 入口误链到博物馆，或用户要求继续但入口没有记录 | 第一版候选保留了博物馆的文件，却仍更新了采样文档。修订后，两种情形都询问缺失的依据，文件字节未变。 |
| 多个空间共用一份老记录 | 只移除采样的完成段落，博物馆等待馆方补充排期的文字和入口仍在。 |
| 从零搭建，等资料到达后交给另一位读者 | 第一位在同目录建立采样入口和独立进度文件。第二位在新会话用后来提供的潮汐资料补全指南、退役这条进度，并保留博物馆的文件。 |

另一次普通采样提问直接从指南给出时间，没有触发搭建工作。早期候选的只读会话曾搜索整个目录，另一轮还替缺少依据的空间创建了新记录。最终规则把查找限定为入口的进度链接或已有约定，并说明缺少依据时停在哪一步。一次正确的终态不能证明所有读取都在范围内，因此这里也检查了工具调用。并行写同一个入口、旧版写入端混用和跨机器恢复都未在这些试验中覆盖。混用写入端的要求见[安装说明](../INSTALL.md)。

## 撤回许可与列出影响需要两个完成条件

旧连接器拿到整源撤回请求后，先在内存标记撤回，再读取绑定文档寻找已经产生的引用，最后写状态。在真实 CLI 第一次打开绑定文档时让进程退出，随后用新进程查询，5.7 回报 `active`。这是本次人为设置的中断点，能证明保存顺序存在缺口，不能用来估计生产故障频率。

5.8 在持有原有状态锁时先原子保存撤回及首次理由，再生成影响报告。替换状态文件之前发生故障，原状态保留。已经保存之后，盘点故障会报告“已撤回，影响报告未完成”。新进程可以查询状态、继续盘点，重试保留首次理由。缺少绑定文件会列为缺口。旧版中断若留下 `active`，仍需重试。撤回只管这个来源任务以后能否处理资料，已有文档的更正或删除仍由各自负责人处理。[来源契约](../skills/ssot-doctor/references/source-integration.md) · [真实 CLI 中断与重试测试](../tests/context/test_source_contract.py)

两条命令过去还会为每条来源记录重新打开每个绑定文件。对同一份 128 条记录、4 个绑定的样本，旧版查询和撤回各尝试打开文件 516 次，新版各 4 次。文件别名保留各自身份。我们对照了两个版本返回的完整 JSON，包括重复标记数、移动前的收据、移动后的绑定和无法打开的文件，各字段相等。单次本机查询从 0.316 秒到 0.024 秒，撤回从 0.322 秒到 0.030 秒。这里没有计量日常对话成本，盘点结果也可能在另一个写入者随后修改文档时过时。[逐次观测](../tests/benchmark/results/context-maintenance-5.8.json)

## 哪些问题值得接着投入

| 使用者需要完成的事 | 当前证据与下一项能改变决定的试验 |
| --- | --- |
| 从真正的工作目录启动就能找到项目约束 | Codex 0.170.0 的零模型发现检查中，父仓库根目录和其普通子目录都能看到六个 skill 及接线指令。独立子 Git 仓库只在本地安装并接线后看到了它们。现行安装说明已描述这个边界。后续应在真实多仓任务中检查进入子仓后能否正确应用父级决定；发现列表本身只能证明可见性。 |
| 小项目先获得有用记忆，也能守住不显眼的保护规则 | Neon 首推轻量起步。5.7 已有两个小样本的成本和交接数据，尚欠缺“首次搭建加上随后几项业务工作”的比较。优先比较已有权威文档的小项目与暗藏例外的项目，分别测遗漏、返工和总成本，再决定是否开放更轻的入口。 |
| 依据变了，后人仍能执行有效的决定 | 在 5.7 的展览收货试验中，场地容量从十二格降至八格。写入者修订调查与收货说明，冷读者从维护文档正确判断十二箱不能一次进入、四箱在有空位时可独立处理。只有登记负责人能改接货安排，每次交付仍用一份清单。这个两层依赖样本支持沿用现有规则。下一步要测没有直接交叉引用的多次修订，以及撤回后从旧会话补录会不会重新带回材料。 |
| 从合并过的历史中找回决定理由 | 合成历史的主线只有两次提交，完整范围有四次，决定理由仅在分支的一条空提交正文中。用户明确点名合并分支时，5.7 的实际读者读到了该原文，准确保留显示屏必须写 `Pier` 的理由、访客地图可以用 `Berth` 的例外，并更新了已检查到的提交位置。普通未点名的补录、冻结 owner 夹在长区间中间、真实团队的合并方式仍需取样，再决定是否改变默认遍历。 |
| 换了负责人，上一任的决定还能否修改 | 现有协议能保存接受人和原话。两处空间出现不同负责人时，仅凭职务名称无法确定谁有权修改哪条决定。下一次应比较明确的局部交接与只有人事任命的对照，再判断问题出在空间入口、决定记录还是宿主授权。 |
| 长期维护值得投入 | 本轮没有测几周内的自然使用。更有区分力的指标是同类任务少了几次重复解释、错误交接和人工修正，及其维护开销。两条兼容名称继续复用现有 skill，这些需求目前均无需新增常驻台账。 |

下一轮建议优先测“资料撤回后再次补录”及“轻量起步加三次后续业务任务”。前者决定现有来源标记和人工复核能否阻止旧材料重新进入知识文档；后者决定降低搭建成本是否会把遗漏和返工推迟到以后。

## 讨论与复验

Antigravity 与 Claude Code 都先收到相同的 5.7 仓库快照并独立给出优先级，随后在各自原会话里质询复现结果及候选设计。Antigravity 请求档位为 `gemini-4-neon-xhigh`，返回型号标识为 `gemini-4-neon`。Claude Code 两轮用量回执均为 `claude-opus-5-5`。Neon 提出的误链和旧进度兼容问题进入试验。cc 要求区分保存失败与报告失败，并对读取优化做别名、移动和缺失文件的等价检查。两者对轻量 Bootstrap、发现入口的首轮排序不同；复现后均将撤回持久化列为第一优先。两场讨论用于设计，行为证据来自独立安装和工具运行。

可重复的采样场景使用正式安装器、隔离工作目录和全新 Codex 会话。共 24 个 Terra medium 原生会话，包括基线、失败候选、修订、对照和冷交接。合计 157 个模型响应，输入 3,393,761 token（其中缓存 2,989,824），输出 24,949。两位设计顾问和协调会话另计。逐次回执摘要、文件变更和哈希见[试验记录](../tests/benchmark/results/context-maintenance-5.8.json)。这些是一次一条件的小样本。

在仓库根目录执行以下命令。前两项跑机械回归。最后一项准备一次新的隔离试验。按[原生评测环境说明](../tests/benchmark/README.md#prepare-and-run)配置后，显式加 `--run-models` 才会调用模型。可选场景和用户任务见[试验入口](../tests/benchmark/space_setup.py)。

```bash
python3 tests/test-ssot-check.py
python3 tests/context/test_source_contract.py
python3 tests/benchmark/space_setup.py --case mismatch --bundle . --output /tmp/ssot-58-mismatch
```
