# 协议 5.23 长期膨胀自动发现、主动归并压缩与分层格式实测

**2026-11-26，围绕消费空间在长期演化中出现的“用户很少主动察觉入口、温层文档、冷索引与临时条目持续膨胀，且文档缺乏自顶向下的冷热分层与防截断写法”问题，基于 `5.22`（提交 `4f4e9bf`）为基线在 `codex-cli 0.172.0` + `gpt-6.1-terra`（`medium`）上完成了两轮反向平衡冻结配对试验（合计 22 组配对、76 次隔离原生回合，Linux `bwrap` 隔离 + 官方 `install.sh --quickstart --agent codex --scope project` 接线）。第一轮诊断暴露出 4 项具体写时与路由缺陷，据此精准修补为候选 v2 并在第二轮 11 组 38 回合全量确认复验中全部验证生效，最终采纳候选 v2 作为协议 `5.23`。** 协议 `5.23` 保持 `ssot_format: 4`/`5` 完全向后兼容、常驻技能目录与受管指令块 `+0 B` 增量，并基于两轮完整实测数据动态微调了 4 项非常驻按需加载的 CI 预算上限；完整两轮脱敏机读回执见 [`tests/benchmark/results/2026-11-26-auto-compaction-layering-v5.23.json`](../tests/benchmark/results/2026-11-26-auto-compaction-layering-v5.23.json)。

## 背景与长周期膨胀根因

协议 `5.22` 解决了单次决策替代时的温层历史归并问题，但从完整生命周期与文档分层形式看，长期使用仍存在五类用户几乎不会主动喊停的结构性膨胀与误报漏洞：

- **机械自动发现存在盲区与冷档误报：** 旧版 `ssot-check.py` 仅在文档超 16,000 字符后才提示日期标题堆积（漏掉 8–16 KB 的早期流水膨胀），完全不检冷索引重放单元格（`decisions/README.md` 单元格动辄 400–540 字符）、入口大节膨胀、已完成 `- [x]` 勾选列表和无日期多主题巨型文档；更糟的是，旧版未对 `decisions/` 冷归档与 `invariants/retired.md` 冷退役分片免检，导致 `ssot-check.py` 在冷归档上反复误报 `WARN`（在本次两轮 `T5` 实测中，基线 `5.22` 两次都被自己的误报诱骗去拆分健康的 `SSOT/decisions/0001-history.md`）。
- **格式 5 单文件流水账与单文档快路径盲区（`5.22` 的 `R2_U3` 边界）：** 当格式 5 空间沿用单文件 `decisions.md` 且未授权新建文件时，单条记录走 `$ssot-closeout` 单文档快路径直接末尾追加，既无法安全拆文件也缺乏文件内冷热分层，导致启动必读不断膨胀。
- **跨生命周期残留与写时/建库矛盾：** 单次任务验收回执、已解决的 `Open questions`/`Known gaps`、条件已满足的临时绕行（workaround）、已关闭的入口任务卡片、以及建库/追平留下的 `.ssot-work/` 临时目录缺少统一清理闭环；同时 `area-mining.md` 原文与精炼登记行规则冲突，入口模板也仍把不断增长的 `## Invariants` 排在 `## Open questions` 之上，使阻塞性待决问题易被截断。
- **无区分的“压缩边界”会引发越权或高成本误读：** 若不严格区分“已触及 SSOT 文件的原地安全压缩”与“未触及文件/外部 owner/首次分片/确认规则正文的一行提议”，Agent 要么借普通 PR 劫持无关 diff，要么因看到未触及文件的检查提示而额外打开大文档浪费数万 token。

## 协议变更四问（[`CONTRIBUTING.md`](../CONTRIBUTING.md#changing-the-protocol)）

1. **这属于通用协议职责吗？** 属于。跨格式 4 与格式 5 的机械膨胀自动发现、冷热目标统一识别（消除冷归档误报）、写时与 Doctor 主动压缩边界、单文件固定布局的文件内冷尾分层，以及自顶向下的模板与写作格式约束，都是决定 SSOT 在数月乃至数年后是否依然可读、不截断、不误删的通用产生过程机制。
2. **它替代或新增了什么？** 本次 `5.23`（候选 v2）在保持常驻技能目录（`508 B` / `677 B`）与受管指令块（`1,415 / 1,339 / 1,123 / 1,063 B`）**`+0 B` 增量**的前提下，形成“机械发现 -> 写时/Doctor 分级行动 -> 模板与分层防膨胀”的单一归属闭环：
   - **机械自动发现与冷档免检（[`ssot-check.py`](../skills/ssot-doctor/assets/scripts/ssot-check.py)，`96,534 / 98,304 B`，`187/187` 单测，AST 白名单零回退）：** 引入统一冷层分类（`decisions/`、已结题 `research/`、`archive/`、`history/`、`*-history.md`、`invariants/retired.md` 及 `ssot_tier: cold`，同时支持 `ssot_tier: warm` 与 `Status: active` 豁免，并对冷分片混入活跃规则发出 `WARN`）；支持文件尾冷读标记（`## History (cold)` / `## Archive (cold)` / `` `## 历史记录（冷读）` `` / `` `## 历史归档（冷读）` `` / `<!-- ssot:cold -->`），并检测倒置冷尾与 >32 KB 截断风险；新增 8–16 KB 早期日期标题堆积 `INFO`、>16 KB 多主题 `>=6` H2 巨型文档拆分提示、冷索引 >8 KB 与 `>250`/`>350` 字符重放行检测、入口单节 >4 KB 提示、已完成 `- [x]` 清单检测，并在摘要前输出**单行自包含** `INFO  .  compaction candidates (N): ...`（对干净仓库输出 0 行；对格式 4 温层指向独立冷归档 `decisions/`/`*-history.md`，对格式 5 保留固定单文件冷尾选项，对外部 owner 显式标注 `external owner -> propose ...`，对入口超 50 行与退役项合并给出具体分片目标）。
   - **分级压缩边界与零多余读取守卫（[`context-tiering.md`](../skills/ssot-preflight/references/context-tiering.md)、[`ssot-closeout/SKILL.md`](../skills/ssot-closeout/SKILL.md)、[`decision-capture.md`](../skills/ssot-closeout/references/decision-capture.md)、[`batch-closeout.md`](../skills/ssot-closeout/references/batch-closeout.md)、[`context-spaces.md`](../skills/ssot-preflight/references/context-spaces.md)、[`ssot-doctor/SKILL.md`](../skills/ssot-doctor/SKILL.md)）：** 在 `context-tiering.md#compaction-boundaries` 单点确立三级边界——对已触及的授权 SSOT 文件自动原地归并现行规则、默认外迁历史至独立冷文件（仅在固定单文件布局使用末尾 `## History (cold)` / `` `## 历史记录（冷读）` ``）、直接删除单次任务验收回执与已解决的临时条目（`Open questions`/`Known gaps`/条件已满足的 workaround/已完成 `- [x]`/已关闭任务卡片）、压缩触及行冗余 `Source`（严守确认规则 `ID`/`Kind`/`Rule`/`Status` 不变）并将触及冷索引压成一行定位器；对未触及膨胀、外部 canonical owner、首次分片/拆目录、格式 5 多文件拆分或改写确认 `Rule` 正文，**绝不打开未触及文件或无关参考文档**，直接从 `compaction candidates` 摘要转述为一条具体的一行提议；在 `$ssot-closeout` 单文档快路径补齐多日期流水文件的原地顶部现行汇总 + 尾冷读分层；在 `$ssot-doctor` 按“热入口 -> 活跃分片 -> 温层 -> 冷索引 -> 半持久面”排序输出并修复，完成后清理 `.ssot-work/`。
   - **分层结构、写作格式与双语模板（[`memory-layout.md`](../skills/ssot-preflight/references/memory-layout.md)、[`memory-model.md`](../skills/ssot-preflight/references/memory-model.md)、[`writing-memory.md`](../skills/ssot-preflight/references/writing-memory.md)、[`task-continuation.md`](../skills/ssot-preflight/references/task-continuation.md)、[`mining.md`](../skills/ssot-bootstrap/references/mining.md)、[`area-mining.md`](../skills/ssot-bootstrap/references/area-mining.md)、[`bootstrap.md`](../skills/ssot-bootstrap/references/bootstrap.md)、[`migration.md`](../skills/ssot-bootstrap/references/migration.md) 及 18 份双语模板）：** 入口推荐顺序将 `## Open questions` 提至 `## Invariants` 之前（向后兼容旧顺序），写作规范在“一段一行”基础上补充短段（约 2–4 句 / 400–600 字）与原子要点约束以消除 >1,000 字符文字墙，明确不变量六列分栏规范并修正 `area-mining.md` 矛盾，补齐格式 5 模板与格式 4 对齐、冷索引一行定位器、`decision.md` 的 `supersedes NNNN` 与底部 `## Source excerpt`、`research.md` 的 `Status:` 元数据及标准 workaround 写法。
3. **验证层级是否匹配影响范围？** 是。两轮试验在 Linux `bwrap` 与官方项目级安装环境下共运行 **22 组反向平衡冻结配对（76 次隔离原生 `gpt-6.1-terra` `medium` 会话）**，覆盖未见领域的格式 4 / 格式 5、中文 / 英文、写入 -> 常规读取 -> 冷回溯、Doctor 授权修复、同语义分层格式 A/B 对照以及 5 组安全与零回归反例。全部 **76/76 会话**逐条核验 `native_models=["gpt-6.1-terra"]`、`native_reasoning=["medium"]`、`completed=true`、`returncode=0`、`usage_source="native"`、只读阶段 `workspace_changed=false` 及冻结树 SHA-256 事前事后一致；4/4 零模型 `codex debug prompt-input` 发现探针（`en/zh × F4/F5`）确认目录与受管块均为 `+0 B`。离线全量验证套件 11/11 全部绿灯（`test-ssot-check.py` 187/187、`test-precommit-hook.py` 27/27、`test-installer-e2e.sh` 202/202、`benchmark` 71/71、`context` 99/99、`shellcheck` 0 警告）。
4. **整任务净收益与代价是什么？** 在第二轮确认试验（候选 v2，11 组 38 会话，双方质量与安全 100% 通过）中，候选 v2 将**全新常规读者总输入降低 `15.78%`**（`300,097 -> 252,754`）、**工具返回字节降低 `50.20%`**（`119,011 -> 59,267 B`）、**API 往返降低 `11.76%`**（`17 -> 15`）；将**冷回溯读者总输入降低 `12.47%`**（`268,742 -> 235,230`）、**工具返回字节降低 `66.00%`**（`147,744 -> 50,236 B`）；全 19 对汇总工具输出字节 **`-12.64%`**（`817,180 -> 713,887 B`）、未命中缓存输入 **`-11.73%`**（`322,586 -> 284,750`）、输出 token **`-0.21%`**、总 API 往返 **`88 -> 88`（`0.0%`）**。代价是写入阶段因主动执行一次性的温层外迁、回执清理或结构提议，输入微增 `+10.11%`（全 19 对总输入 `+3.03%`，由第一轮 `+7.82%` 大幅收敛），但该一次性写时投入在后续每一次常规读取和冷回溯中均立刻回本并持续复利；同时彻底消除 `S4`/`T5` 冷归档误报，并保持 100% 安全与小仓/错字零回归。

## 第一轮诊断发现与向候选 v2 的四项因果修补（透明披露）
