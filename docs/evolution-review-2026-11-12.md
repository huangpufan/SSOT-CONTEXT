## What the project is for

The useful unit is a person or agent continuing a task, not a collection of Markdown files. They need to know the situation, current result, constraints, responsible owners, why choices were made, which evidence supports them, what remains uncertain and which next actions are authorized. Information can exist yet fail at discovery, comprehension, trust or application. Each boundary needs an appropriate owner: the entry routes; content owners explain; original sources support; the acting agent reconciles interpretation; tools verify observable file/state contracts; people settle protected choices and permission.

Development and general spaces share these needs. Software has executable behavior, Git history and mined protection candidates; a research or creative space can instead preserve authorized testimony or experience without code or a future-decision test. Keeping these differences conditional avoids forcing either domain into the other's lifecycle. The current four primary skills still correspond to distinct task moments: reading, setup, upkeep and explicit inspection. No observed failure warrants another skill, a second ledger or merging their permission boundaries.

Knowledge changes state: provisional interpretations stay uncertain; accepted decisions retain standing until a scoped correction; superseded clauses leave current guidance but retain justified provenance; permission withdrawal limits use separately from physical deletion. These needs persist as models improve. Markdown layout, full-register reading, CLI receipts and agent catalogs are current mechanisms, open to measured alternatives. Better retrieval alone cannot supply missing authority or make stale content true. Aging alone is not evidence that a decision should expire.

The protocol edits stay at shared boundaries: the explicit format-5 return replaces accidental fallthrough; the general checker entry makes an existing structural-check duty executable without importing a software recipe. The source handoff orders existing admission and owner writes, rather than moving prose interpretation into the CLI. Fresh-task guidance documents an existing recovery capability without a reinstatement command or permanent ledger. No reading obligation or consumer format is added for unrelated development tasks, and no budget is increased. Whole-task costs and nearby non-trigger controls are reported in the native evidence below.

These are accepted as bounded evidence gathering, not proof that selective reading should change or that synthetic sessions establish long-term production usefulness. Recursive arbitrary-space discovery is not adopted: explicit entries and authorized wiring retain their purpose; scanning unrelated spaces would add privacy, ambiguity and maintenance costs without a demonstrated unmet authorized path. A stale setup checkpoint has no observed failure here; continuation already has an owner and entry.

Byte-identity conflicts intentionally have no in-place clearing command. The new documentation explains this existing task boundary; it does not make a fresh file grant permission or certify the selected source. Normal retries continue in the existing state.

## Remaining ideas and closure
