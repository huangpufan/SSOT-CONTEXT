# Open judgment and evolving-context evaluation

The deliverable is a practical [Chinese guide](evolving-research-and-creative-projects.md) and an opt-in evaluation path for concrete judgment, useful proposals and scoped actions. Existing protocol 5.3 supported the observed paths; this work does not change the runtime protocol or demonstrate that leaving it unchanged improves behavior.

The user authorized implementation after a needs study and discussion with Opus and Fable. Creative benefits must not offset permission violations, incorrect action, lost knowledge or regressions elsewhere. Calliope remained read-only during this evaluation, without installation or changes. A later user instruction authorizes consumer-project updates and Calliope installation after this repository change passes CI; those follow-on installation results are outside this trial account. Public fixtures are synthetic; no private creative assets or original project decision quotations are published here.

The shared runner checks actual discovery, whole-workspace preservation and immutable evidence. ## Review, calibration and engineering repairs

The coordinator independently read the actual writer snapshots, maintained owners, final answers and consumer deliverables before supplying exact-evidence reviews. Content calibration included two legitimate approaches and meaningful bad variants. The coordinator's anonymous decisions were saved before viewing expected labels. Opus's first calibration confused the c/d result keys despite judging their content correctly; that failed mapping remains recorded. Follow-up checked each path, hash, title and quoted passage. Interface tests that merely accept review booleans are not treated as semantic calibration.

Fable 5.2 was unavailable and returned an error, not a completed review. After the user authorized 5.1, actual `claude-fable-5-1` discussion and follow-up completed. They exposed a wording ambiguity: two feasible theatre approaches must not require changing the already accepted goal. Future fixture wording now makes this explicit; frozen attempts and their rubric remain unchanged. Fable's initial claim that partial-unlock execution was unimplemented was corrected after receiving implementation and actual file evidence. Model discussion helped challenge interpretations; agreement was never a behavior verdict.

The evaluation changes also address concrete engineering risks:

- Prose cases are opt-in, preserving preparation of the original automatic-capture route. A real CLI preparation regression protects that entrypoint.
- Research and operations originals transfer only under explicit roots. Consumer permissions are phase- and arm-specific; required actions must change the actual files, with semantic review checking their contents.
- Partial-unlock floor/stale reject roster edits mechanically. The both-unlocked variant removes inherited restrictions because the latest user instruction releases both; an offline counterexample accepts those edits while rejecting changes to the schedule owner. Effective baseline and observed adjacent consumer instructions remain byte-identical, so those native observations did not need replay.
- Three freezer entrypoints canonicalize both the output and allowed temporary roots. A macOS-style `/tmp` alias simulation first reproduced rejection; regression checks now accept the equivalent canonical location and reject real outside paths. This repairs offline preparation, not Linux sandbox portability. Native execution remains Linux-only; actual macOS CI is a separate check.

## Additional creative critique

A separately requested open Carbon Medium discussion examined the existing material and extended its read-only investigation. It challenged the small, clean fixtures and proposed examining long revision chains, proposals that obey explicit rules yet lose the intended effect, and use of still-frozen mixed-version documents. These are useful unmeasured directions, not evidence that the 15 observed turns failed or that the protocol caused poor generation.

The guide incorporates four bounded practices: rewrite repeatedly patched prose while preserving all still-valid meaning and sources; keep the unaffected side of a correction rather than swinging to its opposite; use the still-valid parts of frozen material while distinguishing delayed drafts, coexisting old reality and historical observations, without reinterpreting live v1 software as v2; and distinguish adoption from testing in the actual medium, offering proportionate samples without imposing a new prerequisite. These additions do not add runtime rules or a required schema.

The critique's strong causal claims were not accepted as findings. Keyword occurrence is not a failure rate, long entry text does not by itself establish generation harm, and an audit-like document does not identify protocol wording as its cause. Blanket bans on negative examples, automatic retirement-row removal, fixed example counts and global read-overrides would also risk lost reasons, permissions or actual version semantics. No private project assets or detailed creative quotations are reproduced here. Both Carbon phases completed in one AGY cascade with actual `gemini-4-carbon`, enum `MODEL_PLACEHOLDER_M437` and display `Gemini 4 Carbon (Medium)`. The follow-up retained a provider unexpected-EOF error at step 50 followed by a complete response at step 51, without a coordinator resend or new tools. The final 12 generator-usage records are partitioned by step indices; the initial snapshot is a subset and is not added again. The seven frozen starting inputs remained unchanged. Additional discussion metadata is separate from Codex tokens and dollar snapshots; full private quotations remain local.

## Protection and limits

`skills/`, `install.sh` and `VERSION` remain byte-identical to source `fd426ba`; protocol metadata remains 5.3. Shared-runner offline regression covers old policy cases, exact-scope failures, observation failures, installed continuation and reporting. Benchmark tests pass 65 cases, the complete context offline suite passes 76, and bundle shape passes 57 checks. README links expose the guide without adding runtime loading or obligations. Installer/checker implementations were not changed.

This is source/runtime preservation plus scoped regression evidence. No new native format-4 or ordinary-undeclared trial was run for identical runtime instructions, and comprehensive cross-domain absence of regressions is not established. Subjective artistic appeal, real creative adoption, actual repair/tour operation, universal reliability and performance superiority remain unproven. No protocol candidate was necessary on the observed tasks; this does not mean no future case can reveal one.

The tests remain opt-in billable tools; CI runs offline checks only. [HANDOFF](../tests/benchmark/HANDOFF.md) owns the runner/review procedure, [METHOD](../tests/benchmark/METHOD.md) owns evidence interpretation, and the [machine account](../tests/benchmark/results/open-judgment-2026-11-14.json) owns frozen identities, phases, receipts, discussion-cost snapshots and archive mapping. Claude session cost snapshots can include prior research and overlap across resumed calls; they are retained without summing them as independent expenses.
